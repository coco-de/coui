# RefreshTrigger

스크롤 가능한 콘텐츠를 아래로 당겨서 새로고침을 트리거하는 컴포넌트입니다. iOS와 Android 스타일의 당겨서 새로고침 패턴을 구현합니다.

## 사용 시기 (When to Use)

**이 컴포넌트를 사용하세요:**
- 소셜 피드, 뉴스 목록처럼 최신 데이터를 수동으로 불러와야 할 때
- 모바일 앱에서 네이티브 pull-to-refresh 패턴을 구현할 때
- 스크롤 가능한 영역의 내용을 사용자가 직접 갱신할 수 있어야 할 때

**대신 다른 컴포넌트를 사용하세요:**
- `Loading`: 자동 새로고침 또는 페이지 로딩 중 표시에
- `Progress`: 작업 진행 상태를 퍼센트로 표시할 때

## 기본 사용법 (Basic Usage)

Flutter와 Web 모두 동일한 `RefreshTrigger` API를 사용합니다.

<Tabs groupId="platform">
  <TabItem label="Flutter" value="flutter">

```dart
// 기본 당겨서 새로고침 — 스크롤 제스처로 stage가 자동 구동됩니다.
RefreshTrigger(
  onRefresh: () async {
    await fetchLatestData();
  },
  child: ListView(
    children: const [
      Text('받은편지함'),
      Text('임시 보관함'),
      Text('보낸편지함'),
    ],
  ),
)

// 당김 거리 / 인디케이터 스타일 커스터마이징
RefreshTrigger(
  onRefresh: () async => fetchLatestData(),
  minExtent: 60,
  maxExtent: 200,
  refreshTriggerStyle: const CoreRefreshTriggerStyle(
    refreshingTextStyle: CoreTextStyle.token(
      CoreTextStyles.labelLarge,
      color: CoreColor.token(CoreColors.primary),
    ),
  ),
  child: ListView(children: items),
)
```

## Props / Parameters

`W`는 Flutter의 `Widget`, Web의 `Component`를 뜻하는 스크롤 콘텐츠 타입입니다. min/maxExtent는 논리 px 단위의 당김 거리이며 완료·복귀 시간은 스타일의 Duration입니다.

| 속성 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `child` | `W` | 필수 | 새로고침 대상 스크롤 가능한 콘텐츠 |
| `stage` | `CoreRefreshStage` | `idle` | 인디케이터 lifecycle 단계 (controlled) |
| `direction` | `CoreRefreshDirection` | `vertical` | 당김 제스처 축 |
| `reverse` | `bool` | `false` | 반대쪽 가장자리(하단/우측)에서 시작 |
| `pullText` | `String?` | `null` (활성 로케일 문구) | `idle` 단계 라벨 |
| `releaseText` | `String?` | `null` (활성 로케일 문구) | 임계값 초과 `pulling` 단계 라벨 |
| `refreshingText` | `String?` | `null` (활성 로케일 문구) | `refreshing` 단계 라벨 |
| `completedText` | `String?` | `null` (활성 로케일 문구) | `completed` 단계 라벨 |
| `minExtent` | `double` | `CoreRefreshTriggerStyle.defaultMinExtent` (75) | 새로고침 트리거 최소 당김 거리(px) |
| `maxExtent` | `double` | `CoreRefreshTriggerStyle.defaultMaxExtent` (150) | 최대 당김 거리(px) |
| `onRefresh` | `Future<void> Function()?` | `null` | 새로고침 트리거 시 호출되는 비동기 핸들러 |
| `refreshTriggerStyle` | `CoreRefreshTriggerStyle?` | `null` | 인디케이터의 겉모습 · 크기 · 애니메이션을 바꾸는 값 묶음 |

라벨 4종은 nullable 이라 값을 넘기지 않으면 렌더 시점에 활성 로케일의
`CoUILocalizations` / `CouiLocalizations` 문구로 해석됩니다.

## 동작 스펙 (Behavior)

### 인터랙션

- **당기기**: 스크롤 최상단에서 아래로 당기면 인디케이터 표시
- **충분히 당기기**: `minExtent` 이상 당기면 새로고침 트리거 표시
- **해제**: 당기기를 놓으면 `onRefresh()` 호출, 완료까지 인디케이터 표시
- **중단**: `minExtent` 미만에서 놓으면 복귀

### 상태 전환 (`CoreRefreshStage`)

- `idle` → `pulling`: 최상단에서 아래로 드래그 시작
- `pulling`: `minExtent` 초과 시 라벨이 `releaseText`로 전환
- `pulling` → `refreshing`: 드래그 해제 후 `onRefresh` 실행
- `refreshing` → `completed` → `idle`: Future 완료 후 완료 표시를 거쳐 복귀

### 애니메이션

- 인디케이터 등장: 드래그 거리에 비례한 회전 애니메이션
- 새로고침 중: 무한 회전 스피너
- 복귀: 스프링 효과 300ms

## 사용 가이드라인 (Usage Guidelines)

스크롤 경계에서 당겨 비동기 새로고침을 실행할 때 사용합니다. 직접 누르는 새로고침 액션은 [Button](/components/button), 작업 중 표시만 필요하면 [Loading](/components/loading)이며 이 둘은 pull lifecycle을 소유하지 않습니다. 콘텐츠가 아직 없으면 호출자가 [Skeleton](/components/skeleton)을 구성하고, 새로고침 실패로 콘텐츠가 남아 있으면 [Alert](/components/alert), 대체할 콘텐츠가 전혀 없으면 [EmptyState](/components/empty-state)를 사용합니다.

### ✅ Do

<Callout type="tip">

**onRefresh를 async/await로 올바르게 구현**

```dart
Future<void> handleRefresh() async {
  final newData = await fetchLatestData();
  setState(() {
    _items = newData;
  });
  // Future가 완료되면 인디케이터 자동 숨김
}

RefreshTrigger(
  onRefresh: handleRefresh,
  child: itemList,
)
```

`onRefresh`가 올바르게 완료되어야 인디케이터가 자동으로 숨겨진다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**스크롤할 수 없는 위젯에 RefreshTrigger 사용**

```dart
// ❌ 스크롤 불가능한 위젯에 사용
RefreshTrigger(
  onRefresh: handleRefresh,
  child: Container(
    child: Text('스크롤 없는 콘텐츠'),
  ),
)
```

스크롤 가능한 위젯이 없으면 pull 제스처가 작동하지 않는다.

</Callout>

### ✅ Do

<Callout type="tip">

**브랜드 색상으로 인디케이터 색상 지정**

```dart
RefreshTrigger(
  onRefresh: handleRefresh,
  refreshTriggerStyle: const CoreRefreshTriggerStyle(
    refreshingTextStyle: CoreTextStyle.token(
      CoreTextStyles.labelLarge,
      color: CoreColor.token(CoreColors.primary),
    ),
  ),
  child: feedList,
)
```

브랜드 색상의 인디케이터는 앱의 일관된 시각 언어를 유지한다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**새로고침 중에도 UI가 완전히 차단되지 않도록 주의**

```dart
// ❌ 새로고침 중 전체 화면을 가리는 로딩 오버레이
RefreshTrigger(
  onRefresh: () async {
    showFullScreenLoader(); // 중복 로딩 표시
    await fetchData();
    hideFullScreenLoader();
  },
  child: feedList,
)
```

RefreshTrigger 자체가 로딩 인디케이터를 표시하므로 별도 전체 화면 로딩은 중복이다.

</Callout>

### ✅ Do

<Callout type="tip">

**새로고침 완료 후 명확한 피드백을 제공하세요.**

```dart
RefreshTrigger(
  onRefresh: () async {
    await dataRepository.refresh();
    // 새로고침 완료 후 스낵바 또는 업데이트 시간 표시
    showRefreshCompleted();
  },
  child: ContentList(),
)
```

새로고침이 완료되면 사용자가 데이터가 업데이트되었음을 인식할 수 있도록 명확한 피드백을 제공하세요.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**새로고침 중 추가 인터랙션을 허용하지 마세요.**

```dart
// ❌ 새로고침 중 버튼 클릭 가능
RefreshTrigger(
  onRefresh: handleRefresh,
  child: Column(
    children: [
      ContentList(),
      Button(
        onPressed: handleLoadMore,  // 새로고침 중에도 활성화됨
        child: Text('더 보기'),
      ),
    ],
  ),
)
```

새로고침 중에는 다른 데이터 요청을 막아야 데이터 충돌이나 중복 요청을 방지할 수 있습니다.

</Callout>

## 접근성 (Accessibility)

### 역할

| 플랫폼 | 무엇이 붙는가 |
|--------|--------------|
| Flutter | 컴포넌트 루트를 `Semantics(liveRegion: true)` 로 감쌉니다. role 도 label 도 설정하지 않습니다 |
| Web | 인디케이터 `<div>` 에 `role="status"` · `aria-live="polite"` · `data-refresh-stage="{stage}"` |

Web 루트 `<div>` 는 `data-refresh-direction` 과 호출자 `attributes` 만 싣고 역할을 갖지 않습니다.
당김 제스처를 받는 콘텐츠 호스트에도 두 플랫폼 모두 역할이 없습니다 — 제스처 표면이지 컨트롤이 아닙니다.

### 키보드

| 키 | 동작 |
|----|------|
| — | 없음 |

두 플랫폼 모두 키 이벤트를 구독하지 않습니다. Flutter 는 `NotificationListener<ScrollNotification>` 으로
스크롤 알림만 듣고, Web 은 `pointerdown` / `pointermove` / `pointerup` / `pointercancel` 만 듣습니다.
`child` 로 넘긴 콘텐츠 자신의 포커스·키 처리는 그대로 통과합니다.

### 스크린 리더

- 읽히는 텍스트는 단계별 인디케이터 라벨입니다 — `pullText` / `releaseText` / `refreshingText` /
  `completedText`, 넘기지 않으면 렌더 시점에 활성 로케일의 `CoUILocalizations` /
  `CouiLocalizations` 문구로 해석됩니다. 이 네 값이 스크린 리더에 도달하는 문구를 바꾸는 진입점입니다 —
  Web 인디케이터의 `role` / `aria-live` 는 리터럴 맵이라 `attributes` 로 덮이지 않습니다.
- 상태 통보: 양 플랫폼 모두 라이브 리전입니다. Web 은 polite 라 단계가 바뀔 때마다 라벨이 다시 읽힙니다.
- 라이브 리전의 **범위가 다릅니다** — Web 은 인디케이터 노드 하나, Flutter 는 래핑된 스크롤 콘텐츠
  전체입니다. Flutter 쪽 래퍼에는 자체 label 이 없어 읽히는 문구는 인디케이터가 그리는 `Text` 에서 옵니다.

### 포커스 관리

포커스 대상이 아닙니다. 오버레이가 아니라 스크롤 콘텐츠 위에 겹쳐 그려지는 인디케이터라
진입 · 이탈 · 트랩이 모두 없습니다. Flutter 에 `FocusNode` / `Focus` 가 없고 Web 에 `tabindex` 가 없어
어느 플랫폼에서도 traversal 정지점이 생기지 않으며, 새로고침이 시작되거나 끝나도 포커스는 그대로 머뭅니다.

### 알려진 제약

- **새로고침을 실행할 포인터 외 경로가 없습니다** (WCAG 2.1.1). 위 키보드 절대로 두 플랫폼 다 키를
  듣지 않고, 당김 제스처만 `onRefresh` 를 부릅니다. 대안: state 에
  `GlobalKey<RefreshTriggerState>`(Flutter) / `GlobalStateKey<RefreshTriggerState>`(Web) 를 달아
  `refresh()` 를 호출하거나, controlled `stage` 를 non-idle 로 올려 인디케이터만 구동하고
  새로고침 자체는 호출부가 별도 버튼으로 실행합니다.
- **Web 의 스크롤 호스트를 키보드로 스크롤할 수 없습니다.** `child` 를 담는 `<div>` 가 `overflow-auto`
  로 자체 스크롤 컨테이너가 되는데 `tabindex` 를 받지 않아, 안에 포커스 가능한 요소가 없으면 키보드만으로
  그 영역을 스크롤할 수 없습니다. 이 `<div>` 는 `attributes` 진입점을 노출하지 않으므로 대안은 콘텐츠
  쪽에서 포커스 가능한 요소를 제공하는 것뿐입니다. Flutter 는 호출자의 스크롤러를 그대로 감싸므로
  해당하지 않습니다.
- **인디케이터 경계가 색 강제(forced-colors) 모드에서 사라집니다.** 인디케이터는 배경색
  (`surface` 토큰)과 모서리 반경만으로 카드처럼 보이고 보더도 그림자도 없는데, 색 강제 모드는 그 배경과
  페이지 배경을 같은 시스템 색으로 접습니다. `CoreRefreshTriggerStyle` 에 보더 · 그림자 슬롯이 아예
  없어 대안이 없습니다.
- **Web 의 인디케이터 이동 전환은 '동작 줄이기' 설정을 따르지 않습니다.** Web 은
  `transition: transform {ms}ms` 를 인라인 리터럴로 내보내 CSS 변수(`--coui-duration-*`)를 거치지
  않기 때문에 `@media (prefers-reduced-motion: reduce)` 오버라이드가 닿지 않습니다. `animationDuration`
  에 토큰 값을 넘겨도 같습니다. Flutter 는 같은 값을 `resolveMotionDuration(context, ...)` 으로 통과시켜
  이 설정을 따르므로, 이 축은 플랫폼 사이가 갈립니다. 대안: 호출부가 사용자 설정을 읽어
  `refreshTriggerStyle: CoreRefreshTriggerStyle(animationDuration: Duration.zero)` 를 넘깁니다.

## 크로스 플랫폼 차이점 (Platform Differences)

| 항목 | Flutter | Web |
|------|---------|-----|
| 클래스명 | `RefreshTrigger` | `RefreshTrigger` |
| stage 구동 | 제스처로 자동 + `stage` 명시(non-idle) 시 controlled | 동일 |
| 제스처 감지 | `ScrollNotification` overscroll/pull | pointer 이벤트(터치/마우스) + 스크롤 경계 감지 |
| 인디케이터 | surface 카드 + 화살표/스피너/체크마크 | 동일 (체크마크는 정적 글리프) |

```dart
// 피드 화면에 RefreshTrigger 적용
Scaffold(
  headers: [
    AppBar(

      trailing: [
        // 키보드 접근성을 위한 새로고침 버튼

        ),
      ],
    ),
  ],
  child: RefreshTrigger(
    onRefresh: handleRefresh,
    child: ListView.builder(
      itemCount: feedItems.length,
      itemBuilder: (context, index) => FeedCard(item: feedItems[index]),
    ),
  ),
)
```
