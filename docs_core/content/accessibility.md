# 접근성

## 기준

| 표준 | 적용 |
|---|---|
| WCAG 2.2 AA | 포인터로 조작하는 요소의 최소 터치 타겟 |
| WCAG 2.2.2 | 움직이는 콘텐츠를 멈출 수 있게 함 (Skeleton 맥동) |

## 동작 줄이기

장식은 지우되 정보는 지우지 않습니다. 컴포넌트는 설정을 직접 읽지 않고 duration 토큰의 단계에 따라 결정됩니다.

| 구분 | 대상 | 설정을 켜면 |
|---|---|---|
| 전환 | 열림과 닫힘, 슬라이드, 페이드, hover 반응 | 즉시 (0ms) |
| 표시 | 스피너, 무한 진행률, 토스트 표시 시간, 캐러셀 자동재생 | 그대로 |

| 플랫폼 | 신호 |
|---|---|
| Flutter | `MediaQuery.disableAnimations`, `AccessibilityFeatures.reduceMotion` |
| Web | `@media (prefers-reduced-motion: reduce)` |

> Web에서 토큰이 아닌 duration을 inline으로 넘기면 이 설정이 적용되지 않습니다.

- [Skeleton](/components/skeleton)의 맥동은 표시 단계여도 멈춥니다. 멈춘 블록도 자리표시로 읽히고, 다른 화면을 쓰는 동안 계속 도는 움직임이라 멈출 수단이 있어야 하기 때문입니다(WCAG 2.2.2). 로딩 알림은 그대로입니다.
- iOS 의 '동작 줄이기'도 Android 의 '애니메이션 제거'와 같이 전환을 즉시로 만듭니다. 크기 변화만 빼고 페이드를 남기는 iOS 관례와 다릅니다.
- 실행 중에 바꾼 iOS 설정은 `CoUIApp` 안에서만 이미 그려진 화면에 반영됩니다. `CoUIApp` 밖의 CoUI 위젯은 그릴 때의 값을 읽습니다.

## 고대비와 색 강제 모드

고대비에서는 같은 시맨틱 색 슬롯이 더 강한 값으로 해석되어 컴포넌트가 이 축을 알 필요가 없습니다.

| 플랫폼 | 신호 |
|---|---|
| Flutter | `MediaQuery.highContrastOf` |
| Web | `@media (prefers-contrast: more)` |

Flutter 는 앱이 `highContrastTheme` · `highContrastDarkTheme` 을 주지 않으면 평상시 테마로 그립니다. 고대비가 바꾸는 것은 고대비가 따로 정한 색 슬롯뿐이라 surface 톤은 그대로이고, 전경의 밝고 어두움을 역할마다 뒤집지도 않습니다.

<DesignNote title="색 강제 모드의 포커스 링">

이 모드에서는 box-shadow가 사라지므로 포커스 링은 outline으로 구현합니다. 시스템 색으로 강제되어 남습니다. 링과 컨트롤 사이를 칠하는 밴드는 그림자라서 이 모드에서는 그려지지 않습니다.

</DesignNote>

## 최소 터치 타겟

포인터로 조작하는 요소는 최소 24×24 논리 픽셀의 히트 영역을 가집니다(a11y/pointer-target-min). 터치가 주된 화면에서는 48×48을 권장합니다(a11y/touch-target). 작은 컨트롤은 보이는 크기를 유지하고 히트 영역만 넓힙니다.

## 시맨틱 역할

Flutter Semantics와 Web ARIA role은 하나의 목록에서 나와, 한쪽 플랫폼에만 역할을 추가할 수 없습니다. 전제조건을 채우지 못하면 역할을 붙이지 않습니다. 예를 들어 체크 상태를 말하지 않는 노드에는 체크박스 역할을 붙이지 않습니다 — 붙이면 리더가 "체크 안 됨"을 지어냅니다. Flutter 는 한 노드가 역할과 live region 을 함께 갖는 것을 받지 않으므로, 그런 역할은 두 플랫폼 모두 live region 으로만 냅니다.

## 컴포넌트 문서에서 다루는 것

모든 컴포넌트 문서에 접근성 절이 있어야 하며, 없으면 테스트가 실패합니다.

1. ARIA role과 Semantics 노출
2. 키보드 조작 (다루지 않으면 "없음"으로 표시)
3. 스크린 리더가 읽는 내용
4. 포커스 관리 (진입, 이탈, 트랩)
5. 알려진 제약
