# Dock

모바일/태블릿 앱 하단에 고정되는 **아이콘 + 라벨 기반 내비게이션 바**입니다. 5단계 사이즈(`xs/sm/md/lg/xl`)를 지원하며 `xs`/`sm`에서는 라벨이 자동으로 숨겨집니다.

## 사용 시기 (When to Use)

**이 컴포넌트를 사용하세요:**
- 앱의 최상위 3~5개 탭 사이를 이동할 때
- 현재 위치를 시각적으로 표시해야 할 때 (active item)

**대신 다른 컴포넌트를 사용하세요:**
- **[NavigationBar](/components/navigation-bar)**: bar / rail / sidebar 모드로 섹션 목록을 배치해야 할 때. Dock은 하단 아이콘 중심의 항목 띠입니다
- **[Tabs](/components/tabs)**: 앱 섹션 이동 대신 본문 패널 하나를 전환할 때

## 기본 사용법 (Basic Usage)

```dart
Dock(
  items: [
    CoreDockItemData<Widget>(
      icon: Icon(LucideIcons.house),
      label: '홈',
      isActive: true,
      onPressed: () {},
    ),
    CoreDockItemData<Widget>(
      icon: Icon(LucideIcons.search),
      label: '검색',
      onPressed: () {},
    ),
    CoreDockItemData<Widget>(
      icon: Icon(LucideIcons.user),
      label: '프로필',
      onPressed: () {},
    ),
  ],
)
```

## 사이즈 (Sizes)

높이는 막대의 **최소 높이**입니다. 항목이 그 안에 들어가는 동안 막대는 정확히 이 높이이고, 글자가 커져 더 필요하면 막대가 그만큼 자랍니다 (아래 "막대 높이 (Bar Height)" 절 참고).

| 사이즈 | 최소 높이 (px) | 아이콘 (px) | 라벨 표시 |
|--------|----------------|-------------|-----------|
| `xs` | 48 | 20 | ❌ |
| `sm` | 56 | 22 | ❌ |
| `md` (기본) | 64 | 24 | ✅ |
| `lg` | 72 | 28 | ✅ |
| `xl` | 80 | 32 | ✅ |

사이즈는 막대의 모양도 정합니다. 라벨이 없는 `xs`/`sm` 은 아이콘에 맞춰 촘촘하고, 라벨이 붙는 `md` 이상은 앱마다 폭이 고정된 칸을 씁니다.

| 사이즈 | 막대 여백 (위아래 · 좌우) | 막대 모서리 | 앱 간격 | 앱 칸 폭 | 선택 표시 (모서리 · 아이콘보다 큰 만큼) |
|--------|---------------------------|-------------|---------|----------|------------------------------------------|
| `xs` · `sm` | 6 · 8 | 10 | 6 | 아이콘 폭 | 8 · 사방 3 |
| `md` · `lg` · `xl` | 10 · 10 | 16 | 4 | 48 · 56 · 64 | 10 · 위아래 5 (가로는 칸 폭) |

- 막대에는 `outline-variant` 테두리가 네 변 모두에 그려집니다.
- 막대는 `CoreShadow.md` 그림자를 막대 바깥에만 드리웁니다(`boxShadow`). 서페이스 스타일이 막대를 반투명하게 만들어도 그림자가 막대를 통해 비치지 않습니다. 어두운 테마에서는 그림자가 더 진해집니다.
- 선택 표시는 `surface-container-high` 판으로, 앱 칸 전체가 아니라 **아이콘 뒤**에 놓입니다. 아이콘보다 크게 그려지므로 막대와 앱 칸은 내용을 자르지 않습니다.
- 라벨은 11px 역할(`labelXs`)입니다. 선택된 앱은 SemiBold · `on-surface`, 나머지는 Medium · `on-surface-variant` 이고, 아이콘 색(`activeColor` · `inactiveColor`)과는 따로 정해집니다.
- 앱들은 정해진 간격으로 모여 막대 가운데에 놓입니다. 막대가 넓어져도 앱 사이가 벌어지지 않습니다.
- 반투명 · 배경 흐림은 Dock 의 기본값이 아니라 서페이스 스타일(liquidGlass 등)이 정합니다. 기본 스타일에서 Dock 은 불투명합니다.

## 동작 스펙 (Behavior)

- items를 받은 순서로 표시합니다. item의 `onPressed` 는 탭 · Enter · Space에서 실행하고, null이면 표시용 항목입니다. Dock이 라우팅하거나 `isActive` 를 자동 변경하지 않습니다.
- `isActive` 로 활성 아이콘·라벨·인디케이터를 표시합니다. 활성 인덱스가 바뀌고 항목 수가 같으면 인디케이터가 spring 기반 morph로 이동하며 reduced-motion에서는 이동을 생략합니다.
- `size` 가 라벨 표시 여부와 치수를 정합니다. 바닥 고정·안전영역·내비게이션 스택은 호출부가 구성합니다. 그룹 전체 비활성 플래그는 없습니다.

### 막대 높이 (Bar Height)

`CoreDockStyle.height`(사이즈별 48 · 56 · 64 · 72 · 80)는 막대의 **최소 높이**입니다.

- 항목 행 — 아이콘 · 라벨 — 과 그 위아래 여백, 네 변의 테두리가 이 최소 높이 안에 들어가는 동안 막대는 정확히 그 높이이고, 항목은 세로 가운데에 놓입니다. 글자 배율 1 의 기본 구성에서는 `md` 만 1 을 넘어 65 가 되고(아이콘 24 · 간격 4 · 라벨 줄 15 · 위아래 10 · 테두리 1), 나머지 사이즈는 최소 높이 그대로입니다.
- OS 글자 크기를 키우거나, 더 큰 아이콘 · 라벨 스타일을 쓰거나, 여백(`padding`)이나 선택 표시가 아이콘보다 큰 만큼(`indicatorPadding`)을 키워 행이 더 필요하면 막대가 행만큼 자랍니다. 라벨의 글자 배율과 줄바꿈은 그대로 두고 줄임표도 쓰지 않으므로, 커진 글자는 잘리지 않고 막대가 그만큼 높아집니다.
- 선택 표시는 레이아웃 자리를 차지하지 않고 아이콘 둘레로 겹쳐 그려지므로, 막대는 항목 위아래에 여백과 선택 표시가 아이콘보다 큰 만큼(`indicatorPadding` 위·아래 중 큰 값) 가운데 큰 쪽을 비워 둡니다. 그래야 선택 표시가 막대 밖으로 나가지 않으며, 활성 항목이 바뀌어도 막대 높이는 변하지 않습니다.

**왜 자라는가**: OS 글자 크기는 라벨만 키우고 아이콘과 이 높이는 그대로 둡니다. 높이를 고정하면 사용자가 키워 달라고 한 글자를 막대가 잘라 냅니다(WCAG 1.4.4 는 200% 확대에서도 콘텐츠와 기능의 손실이 없을 것을 요구합니다). 글자 배율을 묶거나 라벨을 감추면 그 정보를 포기해 높이 숫자 하나를 지키는 셈이고, 막대가 자라는 비용은 몇 픽셀입니다.

## 사용 가이드라인 (Usage Guidelines)

### ✅ Do

<Callout type="tip">

**모든 항목에 `onPressed`를 지정하고 3~5개 최상위 탭으로 제한**

```dart
Dock(
  items: [
    CoreDockItemData(
      icon: Icon(LucideIcons.house),
      label: '홈',
      isActive: true,
      onPressed: () => goToHome(),
    ),
    CoreDockItemData(
      icon: Icon(LucideIcons.search),
      label: '검색',
      onPressed: () => goToSearch(),
    ),
  ],
)
```

`onPressed`가 `null`인 아이템은 양 플랫폼 모두 아무 역할도 갖지 않아 탭도 안 되고 스크린 리더에도 안내되지 않습니다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**`label` 없이 아이콘만 넣지 않기**

```dart
// ❌ label 없는 아이콘만 — md/lg/xl 에서도 이름 없는 버튼으로 읽힘
CoreDockItemData(
  icon: Icon(LucideIcons.settings),
  onPressed: openSettings,
)
```

`Icon` 자체는 접근 가능한 이름을 갖지 않아, `label`이 없으면 스크린 리더가 "이름 없는 버튼"으로 읽습니다.

</Callout>

### ✅ Do

<Callout type="tip">

**라벨이 필요한 탭이면 `md` 이상 사이즈를 선택**

```dart
Dock(
  size: CoreDockSize.md,
  items: items,
)
```

`xs`/`sm`은 라벨을 자동으로 숨기므로, 아이콘만으로 뜻이 분명하지 않은 탭에는 `md` 이상을 사용해야 사용자가 각 탭의 의미를 알 수 있습니다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**개수·위치 안내가 필요한 곳에 쓰지 않기**

```dart
// ❌ 6개 이상의 아이템 — "3개 중 2번째" 같은 위치 안내가 없음
Dock(items: sixOrMoreItems)
```

아이템이 `list`/`tablist`로 묶여 있지 않아 개수나 위치가 스크린 리더에 안내되지 않습니다. 3~5개의 최상위 탭에만 사용하세요.

</Callout>

## 접근성 (Accessibility)

### 역할

루트는 양 플랫폼 모두 **navigation 랜드마크**입니다. Flutter 는 `CoUISemantics(role: .navigation, container: true)` 로, Web 은 루트 `<div>` 의 `role="navigation"` 으로 내보냅니다.

랜드마크 이름은 양 플랫폼 모두 `semanticLabel` 이고, 넘기지 않으면 로케일 기본값 `dockLabel`("Dock" / "독")로 채워집니다. Web 에서는 명시한 `semanticLabel` 과 호출자가 넘긴 `attributes` 가 이 기본값을 덮습니다. Flutter 의 navigation role 은 이름이 있을 때만 트리에 올라가므로, 이 폴백이 곧 랜드마크가 항상 announce 되는 조건입니다.

아이템은 `onPressed` 여부로 갈립니다. 눌리는 아이템은 Flutter `Semantics(button: true, selected: item.isActive)`, Web 은 합성된 `Clickable` 의 `role="button"` 이며 활성 아이템에는 `aria-current="page"` 가 추가됩니다. **`onPressed` 가 `null` 인 아이템은 양 플랫폼 모두 아무 역할도 갖지 않습니다.**

### 키보드

Dock 자체는 키를 처리하지 않습니다. 아래 키는 눌리는 아이템에 합성된 `Clickable` 이 제공합니다.

| 키 | 동작 |
|----|------|
| `Tab` / `Shift+Tab` | 다음/이전 아이템으로 이동 — **눌리는 아이템마다 독립적인 탭 스톱** |
| `Enter` | 포커스된 아이템 활성화 |
| `Space` | 포커스된 아이템 활성화 |

**화살표 키 이동은 없습니다.** 툴바/탭 계열에서 흔한 roving tabindex(한 번 진입 후 화살표로 이동) 패턴이 구현되어 있지 않으므로, 아이템이 N 개면 탭 스톱도 N 개입니다.

### 포커스 관리

포커스는 아이템 단위로만 존재하며 `Clickable` 에서 옵니다 — Flutter 는 `FocusNode` + `FocusOutline` 링, Web 은 `tabindex="0"` + `:focus-visible` 링입니다. 누를 수 없는 아이템은 포커스를 받지 않습니다.

Dock 수준의 포커스 트랩·복원·autofocus·`FocusTraversalGroup` 은 없습니다.

### 스크린 리더

- **Flutter**: navigation 랜드마크(지정한 라벨 또는 "Dock" / "독")에 진입한 뒤 각 아이템의 라벨을 읽습니다. 눌리는 아이템은 버튼으로, 활성 아이템은 선택됨(selected)으로 안내됩니다.
- **Web**: 같은 이름의 navigation 랜드마크에 진입한 뒤 각 아이템을 읽습니다. 눌리는 아이템은 버튼으로, 활성 아이템은 현재 페이지(current page)로 안내됩니다.

### 알려진 제약

- 활성 상태 신호가 플랫폼마다 다릅니다 — Flutter `selected` vs Web `aria-current="page"`. 두 플랫폼에서 리더가 읽는 문구가 같지 않습니다.
- 아이템이 `list` / `tablist` 로 묶여 있지 않아 **"3개 중 2번째" 같은 개수·위치가 안내되지 않습니다.**
- 화살표 키 이동과 roving tabindex 가 없어 아이템 수만큼 탭 스톱이 생깁니다.
- 누를 수 없는 아이템(`onPressed == null`)은 역할이 없고, 그 `isActive` 상태는 Flutter 에서만 안내되고 Web 에서는 아무것도 안내되지 않습니다.
- 라벨이 숨는 사이즈(`xs`/`sm`)와 `label` 이 없는 아이템은 라벨 문자열이 **접근성 트리에 들어가지 않습니다.** `Icon` 자체는 이름을 갖지 않으므로 그 아이템은 이름 없는 버튼으로 읽힙니다.

전역으로 적용되는 항목(감소된 모션·고대비·강제 색상·최소 터치 타겟 등)은 [전역 접근성 축](/accessibility)을 참고하세요.

## 크로스 플랫폼 차이점 (Platform Differences)

| 항목 | Flutter | Web |
|------|---------|-----|
| 클래스명 | `Dock` | `Dock` |
| 아이템 타입 | `CoreDockItemData<Widget>` | `CoreDockItemData<Component>` |
| 활성 의미 | `Semantics(selected:)` | 눌리는 활성 항목의 `aria-current="page"` |
| 클릭·포커스 | 합성된 Clickable | 합성된 Clickable |
| 인디케이터 측정 | RenderBox 좌표·GlobalKey | DOM rect·요소 id |
| 렌더링 | `Container` + `Row(center, spacing:)` | `<div>` flex (`justify-center` + `column-gap`) + 토큰 기반 |
| 막대 높이 | `Container(constraints: BoxConstraints(minHeight:))` 안의 내용 크기 `Stacks` | 루트 `min-height` (rem) |
| 위아래 여백 | 항목 행을 감싼 세로 `Padding` | 각 항목(탭 가능하면 그 `Clickable` 루트)의 세로 `margin` |
| 선택 표시 자리 | 아이콘 줄을 감싼 `Stacks` 안의 `Position` | 아이콘 줄 `<div>` 안의 absolute `<div>` |
