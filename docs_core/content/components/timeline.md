# Timeline

이벤트나 활동 내역을 시간 순서대로 시각적으로 나열하는 컴포넌트입니다.

## Live Preview

<LivePreview component="timeline" />

## 사용 시기 (When to Use)

**이 컴포넌트를 사용하세요:**
- 활동 이력, 변경 로그를 시간 순서로 나열할 때
- 각 이벤트에 제목, 날짜, 상세 설명이 필요할 때

**대신 다른 컴포넌트를 사용하세요:**
- `Steps`: 단계 간 진행형 프로세스
- `Stepper`: 다단계 폼

| 속성 | 타입 | 기본값 | 설명 |

## 스타일 시스템 (Style System)

Timeline 의 겉모습(색 · 크기 · 간격)과 안쪽 부품의 스타일은 전부 `CoreTimelineStyle` 하나로 바꿉니다. 시간 컬럼 너비도 겉모습에 속하므로 `timeColumnWidth` 로 정합니다.

<a id="시맨틱-vs-스타일"></a>

### 파라미터와 스타일

- **데이터 입력**: 위젯 파라미터로 직접 (`items`)
- **겉모습 (색 · 크기 · 간격, 안쪽 부품의 스타일)**: `CoreTimelineStyle` 한 곳으로 (아래 필드 표)

<a id="resolve-chain"></a>

### 값이 정해지는 순서

```text
design system default for timeline
  → CoreTimelineTheme.style                    // 프로젝트 공통
  → parent component slot override
  → widget.timelineStyle                       // 인스턴스별
```

안쪽 부품의 스타일 (`timestampTextStyle` / `titleTextStyle` / `descriptionTextStyle`) 은 `CoreTextStyle` 자신의 값이 정해지는 순서로 한 번 더 합쳐집니다.

## 동작 스펙 (Behavior)

- 수직으로 이벤트를 나열
- 점(dot) + 세로 연결선으로 시간 흐름 표현
- 마지막 아이템에는 연결선 없음

## 사용 가이드라인 (Usage Guidelines)

시각·제목·설명을 가진 사건을 나열하려면 Timeline을 사용합니다. 정해진 현재·완료·대기 단계는 [Steps](/components/steps), 단계 이동까지 필요하면 [Stepper](/components/stepper), 설명 없이 여러 구간의 상태를 표시하면 [Tracker](/components/tracker)를 선택합니다. Timeline은 전달 순서대로 표시하고 timestamp 문자열을 날짜로 파싱하거나 정렬하지 않습니다.

### ✅ Do

<Callout type="tip">

**상세 설명이 없는 이벤트는 `description` 생략**

```dart
CoreTimelineItem(title: '처리 중', timestamp: '오전 11:30') // description 생략 가능
```

이유: `description`은 optional 필드이므로 값이 없으면 그 아이템은 제목과 타임스탬프만 렌더링되어, 불필요한 빈 텍스트 블록이 생기지 않습니다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**항목 수가 중요한 화면에 Timeline 단독 사용 금지**

```dart
// ❌ "총 5단계 중 3번째"를 전달해야 하는데 Timeline 만 배치
Timeline(items: orderStatusSteps)
```

이유: Timeline 은 role/label 을 내보내지 않아 스크린 리더가 항목 개수나 순서 관계를 안내하지 못합니다. 항목 수가 중요한 자리라면 호출자가 바깥에 목록 구조나 요약 라벨을 추가해야 합니다.

</Callout>

## 접근성 (Accessibility)

### 역할

**양 플랫폼 모두 없음.** Flutter 위젯 파일에는 `Semantics` 호출이 하나도 없고, Web 은 루트부터 항목 행 · 점 · 연결선 · 텍스트 열까지 전부 role / `aria-*` 없는 `<div>` 로 렌더합니다. 타임스탬프 · 제목 · 설명은 순서대로 배치된 일반 텍스트로 읽히고, 점과 연결선은 빈 상자라 아무것도 발표되지 않습니다.

### 키보드

**없음.** `CoreTimelineItem` 은 콜백을 갖지 않아 항목이 조작 대상이 되지 않고, 양 플랫폼 모두 포커스 가능한 자식이 없어 탭 정지가 생기지 않습니다. Web 생성자는 `attributes` 와 `tag` 는 노출하지만 이벤트 핸들러 파라미터는 노출하지 않습니다.

### 스크린 리더

- **읽히는 순서** — 항목마다 타임스탬프 → 제목 → 설명. Flutter 위젯 트리와 Web DOM 순서가 같습니다.
- **접근 가능한 이름은 없습니다.** 이름을 가질 역할 노드가 없기 때문입니다.
- **라이브 리전이 없습니다.** 항목이 추가되거나 바뀌어도 통보되지 않습니다.

### 포커스 관리

**없음.** 오버레이가 아니어서 진입 시 포커스 이동이 없고, 이탈·트랩도 해당하지 않습니다.

### 알려진 제약

- **목록 시맨틱이 없습니다.** 스크린 리더가 "N개 항목 중 M번째" 를 말해주지 못합니다. Web 은 `attributes` 로 루트에 `role="list"` 를 싣거나 `tag` 를 바꿀 수 있지만, 항목 행은 컴포넌트 내부에서 만드는 `<div>` 라 `listitem` 을 실을 진입점이 없어 루트만 바꾸면 소유자 없는 role 이 됩니다. Flutter 는 항목 단위 진입점이 아예 없으므로, 항목 수가 중요한 자리라면 호출자가 바깥에서 목록 구조나 라벨을 제공해야 합니다.
- **시간 순서가 시각 배치로만 표현됩니다.** 타임스탬프 텍스트 자체는 읽히지만 "이전/다음" 관계는 발표되지 않습니다.
- **항목에 위젯을 넣을 수 없습니다.** `CoreTimelineItem` 의 `title` · `description` · `timestamp` 가 전부 `String` 이라, 로딩 자리에 `Skeleton` 을 넣거나 항목별로 `Semantics` 를 감쌀 방법이 없습니다. 로딩 중에는 `Timeline` 대신 `Skeleton` 트리를 직접 렌더하세요.

> 전역 축(동작 줄이기 · 고대비 · 색 강제 모드 · 시맨틱 역할 · 최소 터치 타겟)은
> [접근성](/accessibility) 페이지가 한 곳에서 다룹니다.

## 크로스 플랫폼 차이점 (Platform Differences)

| 항목 | Flutter | Web |
|------|---------|-----|
| 렌더링 | `Column(spacing:)` + `Row` + 연결선 `CustomPaint` | `div` + CSS flex + `gap` |
| 시간 컬럼 너비 | `CoreTimelineStyle.timeColumnWidth` (logical px) | `CoreTimelineStyle.timeColumnWidth` (rem 변환) |
| 폭 | `Column(crossAxisAlignment: stretch)` 라서 받은 폭을 채운다 | 루트가 블록이라 블록 부모에서는 폭을 채우고, flex 부모(행 · 가운데 정렬 열)에서는 내용 폭이다. 채우려면 호출자가 `classes: 'w-full'` 을 적는다 |
