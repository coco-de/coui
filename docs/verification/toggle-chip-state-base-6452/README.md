## Problem and resulting behavior

An explicit Toggle track base, a raw Chip base, and the default transparent unselected outlined Chip could keep their resting inline background during hover/press. Native/Core composes the state ink over that same base. The original actual browser audit found 52 missing pointer-state paints over 26 light/dark faces. For example, opaque `#334455` with raw alpha ink `0x8012a43c` at existing `.25/.5` weights stayed `#334455` on Web; Native painted `#2b5c4f` / `#237449`.

The two style resolvers keep the exact inline rest fallback as `background-color:var(private-state-fill, exactBase)`. Ordinary state rules select the canonical per-face wash value through the private property. Thus component state paint can change while the original inline priority, caller CSS precedence, actual background-color transition, and resting paint remain intact. Existing `stateLayerWashCss` supplies values; no shared helper or color math is changed.

Toggle keeps the all-default paint branch and uses zero-specificity owned/default guards so implicit and explicitly supplied identical tokens cannot consume each other's private values. Its existing content span receives a private marker; direct content-to-track selectors target this host's track and focus ring, including valid nested prefix/suffix Toggles. This changes content-addressed scope identifiers because the ring rule is part of their existing seed; it does not change the content-hash algorithm or add nodes.

Chip keeps its widget byte-exact, including the passive style-child gate. Passive/disabled bodies paint from the inline fallback without requiring an interactive stylesheet. A value-free, zero-specificity body reset stops state-property inheritance through valid nested Chips. Raw values use canonical private wash values; the preexisting token paint route stays intact. The default transparent Chip now receives the missing native hover/press wash; it is an intentional behavior repair, so this change does not claim all default interactions are unchanged.

## Contract and cascade boundaries

- Product changes are only `toggle_style.dart` and `chip_style.dart`. Both widget files, constructors/const contracts, Core, Native, ThemeConfig, the shared helper, dependency manifests, lockfiles and parity criteria are unchanged.
- Both implementation libraries belong to the Web export closure: Toggle style is exported fully; Chip style is exported through `show`. Existing public AST signatures, constructors/const keywords, constants and export directives/membership are exact. Exported implementation library **bytes** do change. The local closure is 361 files for the default target and 365 for all four conditional alternatives.
- Caller inline background/background-color/shorthand retains its priority, as do caller classes with `!important`. Existing background-image declarations/layers remain. A translucent gradient may reveal a repaired underlying state color; no blanket caller-gradient pixel-invariance claim is made.
- Disabled and passive rest paint remains valid without enabled state rules. Enabled/null-callback Toggle controls were observed on Web. Native's source passes its non-null `handleTap` wrapper while enabled, then returns if the callback is null; that new case was not freshly measured on Native. It is separate from ToggleGroup's preexisting hover/callback boundary. ToggleGroup is unchanged.
- A tested first candidate using ordinary Toggle rest background rules lost inline authority under liquidGlass: raw rest became transparent, explicit tokens were made translucent. That candidate and all negative records are preserved. The final inline fallback fixes the actual regression without preset-specific conditions, gradients, `!important` or specificity escalation. Independent Chrome controls show original rest color/rect exact and owned state values equal in default/liquidGlass. The original default Toggle dark-glass state limitation remains outside this repair.
