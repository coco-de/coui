# ValidationBadge

폼 필드의 유효성 검증 결과를 아이콘과 텍스트로 시각적으로 표시하는 배지 컴포넌트입니다. 비밀번호 강도, 이메일 형식 등 검증 상태 안내에 적합합니다.

## 사용 시기 (When to Use)

**이 컴포넌트를 사용하세요:**
- 비밀번호 설정 시 각 조건(길이, 대문자, 숫자 포함 등)의 충족 여부를 실시간으로 표시할 때
- 아이디, 이메일 중복 확인 결과를 시각적으로 안내할 때
- 폼 필드 아래에 여러 검증 규칙을 체크리스트 형태로 나열할 때
- 입력 진행 중 실시간 유효성 상태를 사용자에게 보여줄 때

**대신 다른 컴포넌트를 사용하세요:**
- `Status`: 시스템이나 사용자 상태(온라인/오프라인)를 표시할 때
- `Banner` 또는 `Toast`: 전체 폼 제출 후 오류 메시지를 표시할 때
- `Text`: 단순한 에러 메시지 텍스트만 필요할 때

// hasInput → !hasInput 이면 pending, 그 외엔 isValid 기준
ValidationBadge.withPending(
  label: '숫자 포함',
  hasInput: password.isNotEmpty,
  isValid: hasNumber,
)

## 변형 (Variants)

### Default (valid)
가장 흔한 success 상태. success container 배경 + check 아이콘.

```dart
ValidationBadge(
  label: '8자 이상',
  state: CoreValidationState.valid,
)
```

### Pending
입력 전 중립 상태. surface container 배경 + 옅은 onSurface 텍스트 + clock 아이콘.

```dart
ValidationBadge(
  label: '대문자 포함',
  state: CoreValidationState.pending,
)
```

### Invalid
실패 상태. error container 배경 + X 아이콘.

```dart
ValidationBadge(
  label: '숫자 포함',
  state: CoreValidationState.invalid,
)
```

### Medium size
typography 가 한 단계 크고 padding 도 더 넉넉한 변형.

```dart
ValidationBadge(
  label: '대문자 포함',
  state: CoreValidationState.valid,
  size: CoreValidationBadgeSize.medium,
)
```

## 동작 스펙 (Behavior)

### 인터랙션
- 표시 전용. 인터랙션 없음.
- `state` prop 변경 시 색상/아이콘 즉시 업데이트.

### 상태 전환
- `pending` → `valid`: 회색 배경 + clock 아이콘 → success container 배경 + check.
- `valid` → `invalid`: success container → error container 배경 + X.

## 사용 가이드라인 (Usage Guidelines)

개별 검증 규칙의 pending/valid/invalid 상태를 작은 배지로 표시하려면 ValidationBadge를 사용합니다. 메시지 한 줄은 [ValidatorHint](/components/validator-hint), 필드와 메시지의 상태 전파는 [Validated](/components/validated), 검증 이외의 상태 라벨은 [Badge](/components/badge)를 선택합니다. 배지는 검증을 실행하지 않고 전달된 state를 표시합니다.

### ✅ Do

<Callout type="tip">

**실시간 검증 + `withPending`로 미입력 단계는 중립 표시**

```dart
Column(
  crossAxisAlignment: CrossAxisAlignment.start,
  children: [
    ValidationBadge.withPending(
      label: '8자 이상',
      hasInput: password.isNotEmpty,
      isValid: password.length >= 8,
    ),
    ValidationBadge.withPending(
      label: '대문자 포함',
      hasInput: password.isNotEmpty,
      isValid: hasUpperCase,
    ),
  ],
)
```

입력 시작 전엔 pending(중립), 시작 후엔 valid/invalid 로 전환됩니다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**입력 전부터 모든 조건을 invalid 로 표시 금지**

```dart
// ❌ 입력 전부터 모든 조건이 빨간 X
ValidationBadge(label: '8자 이상', state: CoreValidationState.invalid)
ValidationBadge(label: '대문자', state: CoreValidationState.invalid)
```

아직 입력 안 된 상태에서 모두 실패로 표시되면 위압감을 줍니다. `pending` 상태 또는 `withPending` factory 를 사용하세요.

</Callout>

### ✅ Do

<Callout type="tip">

**긍정적 메시지로 조건 표현**

```dart
ValidationBadge.fromBool(label: '영문 대문자 포함', isValid: hasUpperCase)
ValidationBadge.fromBool(label: '숫자 1개 이상', isValid: hasNumber)
```

"대문자 미포함"보다 "영문 대문자 포함"처럼 충족해야 할 조건을 긍정형으로 표현하면 더 명확합니다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**너무 많은 조건을 한 번에 표시 금지**

5~6개 이내로 핵심 조건만. 그 이상은 사용자에게 부담.

</Callout>

## 접근성 (Accessibility)

### 역할

- **Flutter** — `Semantics(liveRegion: true)`. 역할 플래그는 세우지 않고 live region 만
  걸며, 이름은 자식 `Text(label)` 에서 옵니다.
- **Web** — 루트 `<span>` 에 `role="status"`(암묵적 `aria-live="polite"`). 이 `role` 은
  호출자가 넘긴 `attributes` 뒤에 병합되어 호출자가 바꿀 수 없고, 나머지 `aria-*` 는 그대로
  통과합니다.

### 키보드

없음. 표시 전용이라 포커스를 받지 않고 처리하는 키도 없습니다.

### 스크린 리더

- **이름** — `label` 문자열입니다. Flutter 는 자식 `Text(label)`, Web 은 라벨 `<span>` 의
  텍스트 노드에서 옵니다.
- **통보** — 양 플랫폼 모두 live region 이라 `state` 가 바뀌어 다시 그려지면 읽힙니다
  (Flutter `liveRegion: true`, Web `role="status"`).
- **상태 아이콘에는 텍스트 대체가 없습니다.** Flutter 의 `Icon` 은 `semanticsLabel` 없이
  `SvgPicture` 를 그리고, Web 의 `<iconify-icon>` 에는 `aria-label` 도 `aria-hidden` 도
  붙지 않습니다. 그래서 리더가 읽는 것은 규칙 문구뿐이고 통과 / 실패 / 대기라는
  **상태 자체는 이름에 들어가지 않습니다** — `valid` 와 `invalid` 가 같은 문장으로
  읽힙니다.

### 포커스 관리

없음. 오버레이가 아니고 포커스 가능 요소도 아니라 진입·이탈·트랩이 모두
해당되지 않습니다.

### 알려진 제약

- **상태를 이름에 넣으려면 `label` 에 직접 씁니다** — `ValidationBadge(label: '8자 이상 —
  충족', state: .valid)`. Web 은 `attributes: {'aria-label': ...}` 로 루트 이름을 덮을
  수도 있지만(호출자가 넘긴 `attributes` 는 `role` 을 빼고 그대로 통과), Flutter 에는 대응하는
  진입점이 없어 `label` 이 유일한 경로입니다.
- **live region 을 끄는 파라미터가 없습니다.** 배지를 나열한 폼에서 조건들이 한 번에
  갱신되면 배지 수만큼 통보됩니다 — 각 배지가 자기 루트에 live region 을 답니다.
  대안: 한 화면에 두는 배지 수를 줄입니다(위 가이드라인의 5~6개 권장과 같은 이유입니다).
