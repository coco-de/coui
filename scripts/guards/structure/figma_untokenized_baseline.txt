# 부재 결정도 폐기도 아니고 **리더 버그**이며, 고치는 방법은 리더에 그 모양의 AST

# 왜 이 게이트가 늦었는가: 이 수는 exporter 의 stderr 안내문 한 줄로만 존재했고

# 아무도 몰랐고, JSON 이 필드 이름을 싣지 않아 "22개(전 21)" 식 보고밖에
# 불가능했다. 이름을 실어야 회귀가 지목된다.

# 2026-08-10: 3. 위 text_area 이름 충돌을 Core rename 으로 해소했다 —
# variant chrome 이 `defaultNormalVariant` / `defaultErrorVariant` 가 되어
# (`CoreTextFieldStyle` 와 같은 철자) `default<Field>` 짝이 참이 됐다. 옛 이름은
# `@Deprecated` 별칭으로 남아 있고, 리더는 `@Deprecated` default 를 건너뛰므로
# 라우팅을 시도하지 않는다 — 대신 이름이 같은 `errorStyle` 필드가 그 창 동안
# `deprecated` 칸으로 세어진다(8 → 9). 별칭이 제거되면 그 필드는 `absent`
# (kind `text`) 로 옮겨간다. 어느 칸이든 실리는 값은 없다 — Core 에 에러 *텍스트*
# 의 default 가 애초에 없고, 두 플랫폼 resolver 가 서로 다른 base role 에
# 얹으므로 공유 default 를 두는 것은 한쪽 렌더를 바꾸는 일이다(별건).
