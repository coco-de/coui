## Props / Parameters

여기에는 **위젯 생성자 파라미터만** 적는다. 겉모습(색 · 크기 · 간격)을 바꾸는 값은
위젯 파라미터가 아니라 `xxxStyle` 슬롯 안에 있으므로 아래 별도 표로 분리한다 — 두 표를
섞으면 이미 없어진 낱개 스타일 파라미터를 광고하게 된다(`docs_api_sync_test.dart` 가 잡는다).

이름·기본값이 공통인 API는 한 표로 적는다. 자식 타입만 플랫폼에 따라 다르면
`W` = Flutter `Widget` / Web `Component`라고 한 번 설명한다. `focusNode`,
`controller` 등 실제 framework-infra 비대칭만 별도 행/표로 보존한다.
렌더러나 상태 어댑터 같은 구현 세부는 Props가 아니라 플랫폼 차이점 절에 둔다.

| 속성 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `prop1` | `Type` | `default` | 속성 설명 |
| `prop2` | `Type?` | `null` | 속성 설명 |
| `child` | `W` | 필수 | 자식 위젯/컴포넌트 |
| `xxxStyle` | `CoreXxxStyle?` | `null` | 겉모습을 바꾸는 값 묶음 (아래 표 참고) |

### `CoreXxxStyle` 필드

이 아래는 손으로 적지 않는다. `CoreXxxStyle.defaultsByVariant`/필드 선언이
이미 코드로 갖고 있는 필드×타입×설명(그리고 variant 가 있으면 필드×variant×토큰)
관계를 markdown 에 다시 손으로 옮기면, 소스가 바뀔 때마다 잊어버리기 좋은 두 번째
사본이 생긴다 — CHANGELOG 링크·버전 문자열과 같은 이유로 여기도 자동 생성이다.

마커 쌍을 붙이고 생성기를 실행한다:

```text
<!-- STYLE_TABLE:BEGIN — auto-generated by `dart run tool/generate_style_tables.dart` (write mode). Do not hand-edit between these markers; edit the CoreXxxStyle source and regenerate. -->

<!-- STYLE_TABLE:END -->
```

```bash
dart run tool/generate_style_tables.dart --write {component-slug}
```

`packages/coui_core/lib/src/component/contracts/{component-slug}/{component-slug}_style.dart`
를 읽어 필드 표(필드·타입·소스 doc comment 에서 뽑은 설명)를 마커 사이에 채운다.
`defaultsByVariant` 가 있으면 필드×variant 기본값 표도 함께 생성된다. 소스가
바뀌면 같은 명령을 다시 돌린다 — 마커 안 내용은 손으로 고치지 않는다(다음 실행이
덮어쓴다). `dart run tool/generate_style_tables.dart --check` 가 CI 에서 drift 를
잡는다.

## 동작 스펙 (Behavior)

### 인터랙션

- **클릭/탭**: 실제 콜백 발생 조건과 전달 값
- **호버**: 실제로 제공하는 반응; 없으면 없다고 명시
- **포커스**: 실제 포커스 반응; 정적 컴포넌트는 자체 입력 처리 없음이라고 명시

### 상태 전환

- 구현된 상태 전이와 제어/비제어 값의 소유자
- 비활성·로딩 중 차단되는 입력과 여전히 허용되는 동작
- 범위 밖 값 처리(clamp/throw/무시), 빈 자식, 연속 입력과 콜백 호출 순서

### 애니메이션

- 실제 토큰(`CoreDuration` / `CoreEasing`)과 단위(ms 등)를 명시
- 진행 중 값이 바뀔 때의 실제 처리; 자체 애니메이션이 없으면 그 사실을 명시

양 플랫폼 구현을 읽고 적는다. 플랫폼별 동작 차이는 아래 차이점 절로 옮기며,
같은 내용을 두 절에서 따로 관리하지 않는다.

## 크로스 플랫폼 차이점 (Platform Differences)

양쪽 구현을 대조하고 실제 차이를 framework-infra, Web 전용 HTML 표면,
soft requiredness, 내부 구현으로 분류한다. 차이가 없으면 확인한 범위를 명시해
"추가 차이 없음"이라고 적는다. 현재 규약이 수용한 soft requiredness와 보존된
WEB-EXTRA는 그 근거와 공통 호출 경로를 함께 적는다. 그 밖의 이름·순서·기본값
발산은 코드 결함 후보로 별도 추적하고, 새 지원 정책으로 바꾸지 않는다.

| 항목 | Flutter | Web |
|------|---------|-----|
| framework-infra | 실제 플랫폼의 포커스/컨트롤러 표면 | 실제 DOM/브라우저 표면 |
| 내부 구현 | 실제 합성/렌더 경로 | 실제 합성/렌더 경로 |
