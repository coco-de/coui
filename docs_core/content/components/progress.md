# Progress

작업 진행률을 시각적으로 표시하는 컴포넌트입니다. 직선형(Progress)과 원형(RadialProgress)을 지원합니다.

## Live Preview

<LivePreview component="progress" variants="default,tone,labelled,segments,indeterminate,radial" />

## 사용 시기 (When to Use)

**이 컴포넌트를 사용하세요:**
- 파일 업로드, 다운로드 등 작업 진행률을 표시할 때
- 목표 달성률, 스토리지 사용량 등 비율을 시각화할 때
- 사용량이 한도에 가까운지 · 작업이 실패했는지처럼 채움 색으로 상태를 함께 말해야 할 때 (`tone`)

**대신 다른 컴포넌트를 사용하세요:**
- `Loading`: 단순 로딩 스피너가 필요할 때
- `Skeleton`: 콘텐츠 로딩 플레이스홀더가 필요할 때
- `Slider`: 사용자가 값을 조절해야 할 때

### 빠른 오버라이드 (Chain)

이미 만든 `Progress` 인스턴스에 스타일을 빠르게 덧붙이고 싶다면 `withStyle` 체인을 쓸 수 있습니다. 생성자의 style 슬롯 인자와 동일하게 동작하지만, 이미 구성된 위젯 위에서 바로 이어 쓸 수 있습니다. `.radius9999`처럼 Core 토큰 상수 이름과 똑같은 이름의 getter도 있습니다 — `withStyle`을 한 번 더 줄인 sugar로, 이름이 곧 값이라(radius9999 == `CoreRadius.radius9999`) 어느 컴포넌트에서 써도 뜻이 갈리지 않습니다.

색 getter(`.primary` · `.success` · `.error` …)는 **채움**(`color`)을 칠하고, getter 가 정한 색은 `tone` 보다 이깁니다. 채움이 무엇을 뜻하는지(한도에 가까움 · 실패) 말하려면 `tone` 을 쓰고, getter 는 tone 에 없는 색에 씁니다. 트랙(`backgroundColor`)은 비워 두므로 어떤 채움 아래서도 같은 중립 트랙(`surfaceContainerHigh`)입니다 — `Progress(value: 0.5).success` 는 success 채움 + 중립 트랙입니다. 트랙 색을 따로 정하려면 `withStyle(CoreProgressStyle(backgroundColor: …))` 를 쓰고, 채움 색을 옅게 따라가는 트랙이 필요하면 `backgroundAlpha` 를 줍니다. `.transparent` 만은 트랙을 비웁니다 — 다른 컴포넌트에서처럼 '바탕 없음' 이라는 뜻이고, 채움을 투명하게 하면 막대가 보이지 않기 때문입니다.

## Props / Parameters

겉모습(색 · 크기 · 간격)을 바꾸는 값은 전부 스타일 하나
(`progressStyle` / `radialProgressStyle`) 에 모입니다. 위젯 파라미터에는
동작 (value / min / max / disableAnimation / segments / showValueText), 종류를 고르는 값 (size / tone),
위젯을 넣는 슬롯 (label / valueLabel / caption / child) 만 남습니다.

직선형의 `label` · `valueLabel` · `caption` 과 원형의 `child` 에 쓰는 `W`는 Flutter의 `Widget`, Web의 `Component`입니다. 직선형 값은 min–max 범위, 원형 값은 0–100 퍼센트 단위입니다.

## 동작 스펙 (Behavior)

### 직선형

- `value` 변경 시 부드러운 width 애니메이션 (300ms ease-in-out)
- 인디케이터에 borderRadius 적용 — 양쪽 둥근 모양
- 트랙 배경 기본값: `surfaceContainerHigh` (채움 색을 따라가지 않는 중립 트랙)
- 채움 색은 `tone` 이 정합니다 — `primary` · `success` · `warning` · `destructive` 가 각각 `primary` · `success` · `warning` · `error` 를 칠합니다. 불확정(`value: null`) 막대도 같은 tone 색입니다.
- 라벨 칸: `label`(왼쪽, 남은 폭을 채움)과 `valueLabel`(오른쪽)이 한 행으로 막대 위에, `caption` 이 막대 아래에 놓입니다. 칸과 막대 사이는 `labelGapStyle` · `captionGapStyle`(기본 8). `label` 없이 `valueLabel` 만 주면 값은 오른쪽에 그대로 있습니다.
- 칸의 글자: `label` `labelMedium` · 600 · `onSurface`, `valueLabel` `labelMedium` · `onSurfaceVariant`, `caption` `bodyXs` · `onSurfaceSubtle`. 칸에 넣은 위젯이 이 스타일을 이어받고, 다르게 하려면 `Text` 체인으로 덮습니다.
- 세 칸이 모두 `null` 이면 막대 하나만 그립니다 — 칸이 생기기 전과 같은 트리 · DOM 입니다.
- `segments` 를 주면 막대가 그 수의 칸으로 나뉩니다. 채워지는 칸은 **지나온 단계 수** —
  `⌊(value − min) / (max − min) × segments⌋` — 이고 나머지 칸은 트랙 색입니다. 단계는
  도달해야 지나간 것으로 셉니다(`value: 0.99, segments: 2` 는 한 칸). 곱셈의 부동소수 오차로
  정수 바로 아래에 떨어진 값(`0.29 × 100` = `28.999…`)은 그 단계에 도달한 것으로 봅니다. 두
  플랫폼이 같은 계산(`CoreProgressContract.filledSegmentsOf`)을 부릅니다.
- 칸은 폭을 똑같이 나누고(Flutter `Expanded`, Web `flex-1`) 높이 · 모서리는 트랙과 같습니다. 칸
  사이는 `segmentSpacing`(기본 `space4`) 입니다. 기본값이 밀도 축의 바닥(4 이하는 움직이지 않음)이라 밀도를 바꿔도 같고, 더 큰 값을 직접 주면 밀도를 따라 움직입니다. 칸 색이 바뀔 때는
  `duration` 동안 `CoreEasing.move` 로 전환합니다 — 연속 막대의 채움 폭과 같은 시간 · 곡선입니다.
- 불확정 막대에는 보여 줄 단계가 없어 `segments` 를 주어도 연속 막대로 미끄러집니다.

### 원형

- 12시 방향(-π/2)에서 시작하는 원형 아크
- `strokeCap: round` — 양쪽 끝 둥근 형태
- `showValueText: true` 시 중앙에 "75%" 형태 표시
- 직선형과 같은 `size`(4단 — `xs2` · `xs` 는 없음) · `tone` 축을 가집니다. 단계가 지름 · 링 두께 · 글자 역할을 함께 정하고, `tone` 이 아크 색을 정합니다. 트랙은 어느 tone 에서나 중립 면(`surfaceContainerHigh`) 입니다.
- `label` · `valueLabel` · `caption` 이 없습니다 — 중앙에는 `child` 한 칸만 있습니다. 직선형과 API 가 갈리는 자리입니다.
- 값 칸(`valueLabel`)은 가장 넓은 읽기 `100%` 의 너비를 미리 잡고 숫자를 끝에 붙입니다 — 9% → 10% → 100% 로 올라가도 막대가 밀리지 않습니다 (숫자는 같은 폭의 자릿수).
- 불확정 막대의 움직이는 채움은 트랙의 35% 입니다 (`indeterminateFillRatio`).

## 사용 가이드라인 (Usage Guidelines)

완료 비율이 알려진 작업은 Progress/RadialProgress로 표시하고 알려지지 않은 작업은 Progress의 `value: null` 또는 [Loading](/components/loading)을 사용합니다. 기다리는 콘텐츠의 모양을 예약하려면 호출자가 [Skeleton](/components/skeleton) 트리를 구성합니다. 값을 사용자가 조절해야 하면 [Slider](/components/slider)를 선택합니다.

두 끝 값을 조절하는 구간 입력은 [Range](/components/range), 서로 다른 시점의 상태 구간은 [Tracker](/components/tracker)이며 단일 완료 비율과 구분합니다.

```dart
RadialProgress(
  value: 75,
  showValueText: true,
)
```

공간이 제한된 카드에서 목표 달성률을 효과적으로 표시합니다.

</Callout>

### Don't

<Callout type="warning">

**진행률이 멈춘 상태에서 아무 피드백 없이 두지 마세요.**

진행이 느리면 "대용량 파일 처리 중..." 같은 텍스트를 추가하세요.

</Callout>

## 접근성 (Accessibility)

### 역할

| | Web | Flutter |
|---|---|---|
| `Progress` | `role="progressbar"` + `aria-valuemin` / `aria-valuemax`, 값이 있을 때만 `aria-valuenow`. `label` 이 있으면 `aria-labelledby`, `caption` 이 있으면 `aria-describedby`. 단계형이면 `aria-valuetext` | `Semantics(value: ...)` — progressbar 역할도 min/max 도 없음. 칸이 있으면 `MergeSemantics` 로 한 노드가 되어 `label` · `caption` 글자가 이름으로 읽힘 |
| `RadialProgress` | `role="progressbar"` + `aria-valuenow` (min/max 없음 → ARIA 기본 0–100) | 없음 — 파일 어디에도 `Semantics` 가 없음 |

- Web 의 `role` / `aria-value*` 는 호출자가 넘긴 `attributes` 보다 **나중에** 병합되어 덮어쓸 수
  없습니다. 그 밖의 속성(`aria-label` 등)은 그대로 통과합니다.
- `Progress` 는 `label` 을 주면 그 글자가 막대의 이름이 됩니다(Web `aria-labelledby`,
  Flutter 병합된 노드의 라벨). `caption` 은 Web 에서 `aria-describedby` 로 이름과 갈라진
  설명이 되고, Flutter 에서는 노드가 하나로 합쳐져 이름(라벨)에 이어 읽힙니다 — 리더가 읽는
  글자는 같지만 이름과 설명을 따로 구별할 수 있는 것은 Web 뿐입니다. `valueLabel` 은 값을 화면에 다시
  쓰는 칸이라 두 플랫폼 모두 읽지 않습니다 — 값은 막대 자신의 값으로 한 번만 읽힙니다.
- `label` 이 없는 `Progress` 와 `RadialProgress` 는 **이름이 없습니다** — 무엇의 진행인지
  알려주는 라벨을 붙이지 않습니다.

### 키보드

해당 없음. 진행률 표시는 포커스를 받지 않고 tab stop 을 만들지 않습니다. 표시 전용
이라 값을 바꾸는 키도 없습니다 — 사용자가 값을 조절해야 하면 `Slider` 를 쓰세요.

### 스크린 리더

- **Web** — `aria-valuenow` 에는 정규화하지 않은 원래 값이 실리고(`Progress(value: 0.65)`
  → `aria-valuenow="0.65"`), `aria-valuemin` / `aria-valuemax` 가 함께 있어 리더가
  백분율을 계산합니다. `value` 가 `null` 인 indeterminate 상태에서는 `aria-valuenow` 를
  아예 내보내지 않습니다.
- **Flutter** — 값은 `min`~`max` 를 0–100 으로 정규화한 **백분율 문자열**(`'65%'`)로
  실립니다. indeterminate 일 때는 숫자 대신 로케일의 로딩 문구를 값으로 내보냅니다 —
  0% 를 읽어 "멈춘 것처럼" 들리는 것을 피하기 위해서입니다.
- **단계형**(`segments`)은 두 플랫폼 모두 백분율 대신 **단계**를 읽습니다 — 활성 로케일의
  문구로 "Step 1 of 2" / "2단계 중 1단계". Web 은 이 문구를 `aria-valuetext` 에 싣고
  `aria-valuenow` · `aria-valuemin` · `aria-valuemax` 는 원래 값 그대로 둡니다. Flutter 는 같은 문구를
  `Semantics` 의 value 로 냅니다.
- 값이 바뀔 때 통보하는 live region 은 어느 쪽에도 없습니다. 진행 상황을 소리로 알려야
  하면 호출자가 별도 라이브 리전을 둬야 합니다.
- `RadialProgress` 의 `showValueText` 가 그리는 `NN%` 텍스트는 Flutter 에서 이
  컴포넌트가 읽히게 하는 유일한 경로입니다.

### 포커스 관리

- **진입 / 이탈 / 트랩** — 전부 없음. 오버레이도 컨트롤도 아니라 포커스를 옮기지
  않습니다.

### 알려진 제약

- **Flutter 에는 progressbar 역할이 없습니다.** `CoreSemanticRole.progressBar` 는 존재
  하지만 `Progress` 는 raw `Semantics(value:)` 만 쓰고 role · `minValue` · `maxValue` 를
  넘기지 않습니다. 리더는 "진행률 표시줄"이라고 안내하지 않고 값만 읽습니다.
  대안: 호출부가 값·최소·최대를 다시 적어
  `Semantics(role: ..., value:, minValue:, maxValue:)` 로 감쌉니다.
- **`RadialProgress` 는 Flutter 스크린 리더에 존재하지 않습니다** — 시맨틱 배선이 전혀
  없습니다. 대안: 호출부에서 `Semantics(...)` 로 감쌉니다. Web 은 역할이 있으나
  `aria-valuemin` / `aria-valuemax` 가 없어 ARIA 기본값 0–100 에 의존합니다 — `value` 가
  0–100 스케일이라 결과는 맞지만 범위를 바꿀 진입점이 없습니다.
- **화면에 라벨을 그리지 않고 이름만 붙이는 진입점은 플랫폼마다 다릅니다.** 보이는
  라벨이면 두 플랫폼 모두 `label` 슬롯이 이름이 됩니다. 보이지 않는 이름만 필요하면
  Web 은 `Progress(attributes: {'aria-label': ...})` 로 통과시킬 수 있고(강제되는 것은
  `role` 과 `aria-value*`, 칸이 있을 때의 `aria-labelledby` · `aria-describedby`), Flutter 는
  호출부가 `Semantics(label: ...)` 로 감싸야 합니다.
- **OS 색 강제 모드에서 진행 위치가 사라질 수 있습니다.** 트랙과 채움이 보더 없이
  배경색만으로 구분되므로 두 색이 같은 시스템 색으로 치환되면 구분이 없어집니다.
  Web 은 그때도 `role="progressbar"` / `aria-valuenow` 로 값 자체는 계속 전달합니다.

## 크로스 플랫폼 차이점 (Platform Differences)

| 항목 | Flutter | Web |
|------|---------|-----|
| 클래스명 | `Progress` / `RadialProgress` | `Progress` / `RadialProgress` |
| 값 범위 | 0.0~1.0 (기본) | 0.0~1.0 (기본) |
| 직선형 렌더링 | `Container` + `AnimatedContainer` | div + inline style |
| 라벨 칸 배치 | 칸이 있으면 `Column[Row(label, valueLabel), Gap, 트랙, Gap, caption]` | 칸이 있으면 `flex flex-col` 루트 아래 같은 순서 — 루트가 `role="progressbar"` 를 유지 |
| 단계형 렌더링 | 트랙 자리에 `Row(spacing: segmentSpacing)` + `Expanded` 칸, 칸 색 전환은 `AnimatedContainer` | 트랙 자리에 `flex` 행 + `column-gap` + `flex-1` 칸, 칸 색 전환은 CSS `background-color` transition — 라벨 칸이 없으면 이 행이 `role="progressbar"` 루트 |
| 원형 렌더링 | `CustomPaint` (`_RadialProgressPainter`) | inline `<svg>` + `<circle>` 2개 (트랙 + `stroke-dasharray` / `stroke-dashoffset` 아크) |
| 애니메이션 | `AnimatedContainer` 300ms | CSS transition 300ms |
