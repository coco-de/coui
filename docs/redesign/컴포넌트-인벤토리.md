## 핵심 발견

1. 상태 표현이 두 갈래: State 축 16개 vs 불린 축 44개(Enabled 24, Disabled 14로 방향 반대, Focus/Focused, Hover/Hovered 혼용). Badge 192 변형.
2. 크기 단계 제각각: 3단계 12, 6단계 11(xs 잔존), 5단계 4, 2단계 2, Icon 10.
3. 컨테이너 반경 제각각: 4, 8, 12, 16, 24 + 오류로 보이는 15(OutlinedContainer), 10.4·2.6(Window).
4. 토큰 연결 양호. 색 미연결은 PhoneInput 8, Mockup 계열(의도). 텍스트 스타일 미적용 16개 컴포넌트(Filter 40, Checkbox 17, Accordion 12 등). 완료 컴포넌트의 pill·파생 반경이 숫자로 들어감(생성기 확인 필요).
5. 많이 품어지는 부품: Icon 60, Button 24, Skeleton 16(내용 자리 용도), TextField 13, Divider 10.
6. 정리: 백업 프레임 13곳, Tabs 프리뷰가 프레임(대조 불가), 설명 없는 컴포넌트 10개, 페이지 섹션 순서 어긋남.

## 1단계에서 먼저 정할 것

1. 상태 표현 방식 통일 (구조 변경, 44개 영향, 코드 공개 API 영향 여부 Claude Code 확인) — **확정** 2026-10-02 (`상태-표현-통일-제안.md` §8)
2. 크기 단계 기준 (xs 제거 시점과 맞춤) — **채택** 2026-10-01. 리디자인 선행 코드 인계 완료 2026-10-07(#5218~#5220 · #5222~#5224). xs 제거(#5221 N+1 · N+2)는 보류 — 리디자인 선행이 아니다
3. 컨테이너 반경 사다리 (작은 요소 4 포함) — **확정** 2026-10-02 (`컨테이너-반경-사다리-제안.md` §7)
4. Skeleton 역할 분리 여부 — **나눈다**(로딩 표시와 슬롯 자리 대역) 2026-10-02. 분리 형태(`.Slot` 대역)와 Skeleton 리디자인(채움 · 반경 · 맥동 · 멈춤 · 알림 · `asSkeleton`) **확정** 2026-10-06, 고아 노드(D7)는 기록만 2026-10-07 (`skeleton-조사.md` §12). 코드 인계 #5277~#5282
5. 떠 있는 표면(Popup) 기준: 반경, 그림자, 테두리 — 반경은 3번에서 확정. 그림자 · 테두리는 **역할별로 하나로**(2026-10-02), 값은 **확정** 2026-10-06 (`떠-있는-표면-기준-제안.md` §8)
6. 휴대폰 배율 (Flutter 1.25배 vs Web) — **확정** 2026-10-07: 두 플랫폼 모두 1배, 1.25 는 앱이 켜는 선택지로 남기고 Web 에도 같은 손잡이를 둔다, 터치 화면의 큰 컨트롤은 크기 단계로 고른다 (`휴대폰-배율-조사.md` §6). 1.25배를 켠 앱에서는 반경만 곱하고 테두리 · 그림자 · 포커스 링은 곱하지 않는다(D8, 2026-10-07). 누르는 영역 하한은 24 를 유지한다(D17, #5306 측정 뒤 2026-10-07). 기본값 1 은 #5316 으로 들어갔다
