# Stepper

사용자가 단계를 클릭하여 이동할 수 있는 인터랙티브 프로세스 컴포넌트입니다.

## Live Preview

<LivePreview component="stepper" variants="default,vertical,disabled" />

## 사용 시기 (When to Use)

**이 컴포넌트를 사용하세요:**
- 회원가입, 결제, 설정 마법사 등 다단계 폼
- 사용자가 이전 단계로 돌아가거나 특정 단계로 점프할 수 있어야 할 때

**대신 다른 컴포넌트를 사용하세요:**
- `Steps`: 읽기 전용 진행 상태 표시 (탭 불가)
- `Tabs`: 독립적인 콘텐츠 간 전환 (순서/진행 개념 없음)

## 기본 사용법 (Basic Usage)

```dart
Stepper(
  currentStep: 1,
  steps: [
    CoreStepItem(label: '계정', description: '계정 만들기'),
    CoreStepItem(label: '프로필', description: '프로필 설정'),
    CoreStepItem(label: '완료', description: '모두 끝났어요'),
  ],
  onStepChanged: (index) => setState(() => _step = index),
)
```

## Props / Parameters

| 속성 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `steps` | `List<CoreStepItem>` | 필수 | 단계 목록 |
| `currentStep` | `int` | `0` | 현재 활성 단계 인덱스 (0-based) |
| `orientation` | `CoreStepperOrientation` | `.horizontal` | 배치 방향 (horizontal/vertical) |
| `onStepChanged` | `void Function(int)?` | `null` | 단계 클릭 시 호출 |
| `enabled` | `bool?` | `null` | 활성 여부. `null` 이면 `onStepChanged != null` 을 따릅니다 — 콜백이 없는 스테퍼는 비활성 색으로 그려집니다 |
| `stepperStyle` | `CoreStepperStyle?` | `null` | 인스턴스 스타일 (Style 시스템 참조) |

## 스타일 시스템 (Style System)

Stepper 의 겉모습(색 · 크기 · 간격)과 안쪽 부품의 스타일은 전부 `CoreStepperStyle` 하나로 바꿉니다. 종류를 고르는 값 (`orientation`) 과 내용 · 동작 (`steps` / `currentStep` / `onStepChanged`) 은 위젯/컴포넌트 파라미터로 직접 넘깁니다.

<a id="시맨틱-vs-스타일"></a>

### 파라미터와 스타일

- **종류 · 내용 · 동작**: 위젯/컴포넌트 파라미터로 직접 (`steps`, `currentStep`, `orientation`, `onStepChanged`, `enabled`)
- **겉모습 (색 · 크기 · 간격, 안쪽 부품의 스타일)**: `CoreStepperStyle` 한 곳으로 (`indicatorActiveColor` / `indicatorCurrentColor` / `indicatorInactiveColor` / `indicatorCurrentBorderColor` / `indicatorInactiveBorderColor` / `indicatorBorderColor` / `indicatorBorderWidth` / `indicatorSize` / `connectorActiveColor` / `connectorInactiveColor` / `connectorThickness` / `indicatorContentGapStyle` / `stepPadding` / `connectorMargin` / `connectorMarginVertical` / `labelGapStyle` / `descriptionGapStyle` / `connectorMinExtent` / `iconSizeRatio` / `labelStyle` / `labelUpcomingStyle` / `descriptionStyle` / `indicatorIconStyle`, 비활성: `indicatorDisabledColor` / `indicatorDisabledBorderColor` / `connectorDisabledColor` / `disabledForegroundColor`)

<a id="resolve-chain"></a>

### 값이 정해지는 순서

```text

  → CoreStepperTheme.style                    // 프로젝트 공통
  → parent component slot override
```

## 동작 스펙 (Behavior)

### 상태 표시

- `currentStep` 미만: 완료 (`primary` 원 + `onPrimary` 체크 아이콘, 라벨 `onSurface`) — 이 단계에서 나가는 연결선은 `primary`
- `currentStep` 인덱스: 현재 (`surface` 원 + `primary` 1px 테두리 + `onSurface` 번호, 세미볼드 라벨) — 나가는 연결선은 `outlineVariant`
- `currentStep` 초과: 대기 (`surface` 원 + `outlineVariant` 1px 테두리 + `onSurfaceVariant` 번호, 라벨도 `onSurfaceVariant`)

현재 단계의 채움 · 테두리 · 번호는 `indicatorCurrentColor` · `indicatorCurrentBorderColor` · `indicatorNumberActiveStyle` 이 정하고, `indicatorActiveColor` 는 완료 단계의 채움만 정합니다. 번호는 `labelMedium` 세미볼드, 가로 라벨은 `labelLarge`(현재 단계만 세미볼드), 세로 라벨은 `titleSmall` 세미볼드입니다. 라벨과 설명 사이는 `descriptionGapStyle`(2)입니다. 연결선은 원에 바로 닿습니다 — 가로 레이아웃의 원과 반쪽 선 사이 여백 `connectorMargin` 과 세로 레이아웃의 원 위 · 아래 여백 `connectorMarginVertical` 의 기본값이 모두 0 입니다.

### 가로 레이아웃의 단계 칸

가로 스테퍼는 같은 폭의 단계 칸을 한 줄로 늘어놓습니다. 폭이 정해진 줄에서 각 칸은 줄 폭의 균등 분할(예: 400 폭의 세 단계는 133.3 씩)이고 원 지름보다 좁아지지 않습니다. 칸 안에서는 원 양옆에 반쪽 연결선이 놓이고, 라벨은 원 아래 가운데에 놓입니다. 두 단계 사이의 연결선은 앞 단계의 뒤쪽 반쪽과 뒤 단계의 앞쪽 반쪽이 칸 경계에서 만나 하나로 이어지며, 첫 단계의 앞쪽 반쪽과 마지막 단계의 뒤쪽 반쪽은 그려지지 않지만 폭은 유지해 원이 칸 가운데에 옵니다. 칸에 다 들어가지 않는 라벨은 칸 안에서 줄바꿈합니다. 폭이 정해지지 않은 줄에서는 Flutter 가 가장 넓은 칸에 맞춰 모든 칸을 같은 폭으로 둡니다.

### 세로 간격과 제목 정렬

`stepPadding`의 기본값은 `CoreEdgeInsets.only(bottom: CoreSpace.space20)`입니다. 마지막 단계에서는 이 authored 패딩을 생략합니다. 제목 첫 줄은 원의 실제 높이와 첫 줄 정렬 메트릭의 높이 차이를 절반으로 나눈 값(최소 0)만큼 내려갑니다. 이 정렬은 간격 토큰과 별도로 계산되며, 마지막 단계에도 적용됩니다. `stepPadding`을 덮어쓰면 마지막 단계를 제외한 각 단계에서 지정한 네 변이 유지되고, 위쪽 패딩에는 이 정렬량이 더해집니다. 여러 줄 제목은 첫 줄을 기준으로 정렬하고 전체 문단 높이만큼 행이 자랍니다.

첫 줄 정렬 메트릭은 Flutter의 `LineMetrics.height`를 기준으로 논리 픽셀 단위로 반올림합니다. Web도 최종 제목의 `1lh`를 정렬 계산 안에서만 같은 단위로 반올림합니다. Web의 실제 줄 높이와 문단 상자는 소수값을 유지하므로, 브라우저 글자 상자의 정확한 중심과 정렬 메트릭의 중심에는 소수 픽셀 차이가 남을 수 있습니다.

### 비활성 상태

`enabled` 가 `false` 이거나(`null` 이면 `onStepChanged == null`) 콜백이 없는 스테퍼는 **흐려지지 않고** 비활성 색으로 그려집니다 — 완료 원은 `disabledContainer`, 연결선과 현재 · 대기 원의 테두리는 `disabledOutline`, 체크 · 번호 · 라벨 · 설명은 `disabledContent` 입니다(`disabledForegroundColor` 한 값). 현재 · 대기 원의 채움은 비활성에서도 `surface` 입니다. 비활성 스테퍼는 `Clickable` 로 감싸지 않으므로 포커스 · 호버 · 눌림 피드백이 없고, 불투명도도 따로 낮추지 않습니다.

### 인터랙션

- 각 단계 인디케이터 클릭 → `onStepChanged(index)` 호출
- 키보드 네비게이션은 표준 `Tab` 순서 따름

## 사용 가이드라인 (Usage Guidelines)

단계 클릭으로 onStepChanged를 통보하는 흐름에는 Stepper를 사용합니다. 단계를 보여주기만 하면 [Steps](/components/steps), 진행 단계와 무관한 패널 선택은 [Tabs](/components/tabs)를 선택합니다. Stepper가 폼을 검증하거나 다음 단계 진행을 자동 승인하지 않으므로 호출자가 상태와 진입 조건을 관리합니다.

### ✅ Do

<Callout type="tip">

**임의 점프 허용 여부는 콜백 안에서 직접 검증**

```dart
Stepper(
  currentStep: step,
  steps: steps,
  onStepChanged: (index) {
    if (index <= step) setState(() => step = index); // 완료된 단계로만 되돌아가기 허용
  },
)
```

`onStepChanged`가 있으면 완료 여부와 무관하게 **모든** 인디케이터가 동일하게 클릭 가능해집니다. 아직 도달하지 않은 단계로의 점프를 막으려면 콜백 안에서 인덱스를 직접 검증해야 합니다.

</Callout>

---

### ❌ Don't

<Callout type="warning">

**읽기 전용으로 쓰려고 no-op 콜백을 넘기지 않기**

```dart
// ❌ 읽기 전용 진행 표시가 목적인데 onStepChanged를 채워둠
Stepper(
  currentStep: step,
  steps: steps,
  onStepChanged: (_) {},
)
```

`onStepChanged`가 `null`이 아니면 모든 인디케이터가 `Clickable`(포커스 링·호버·커서 포함)로 감싸집니다. 진짜 읽기 전용 진행 표시가 필요하면 `Steps` 컴포넌트를 사용하세요. `onStepChanged`를 생략한 `Stepper` 는 `enabled` 가 `null` 일 때 비활성 색으로 그려지므로, 콜백 없이 활성 색을 쓰려면 `enabled: true` 를 명시합니다.

</Callout>

## 접근성 (Accessibility)

### 역할

- **Flutter** — `Stepper` 자신은 `Semantics` 를 하나도 내보내지 않습니다. `onStepChanged` 를 넘겼을 때만 인디케이터가 `Clickable` 로 감싸여 `Semantics(button: true, enabled: …)` 를 받고(`stepper.dart:102`, `clickable.dart:505`), 단계 번호·현재 단계·완료 여부를 알리는 role 이나 상태는 붙지 않습니다.
- **Web** — `onStepChanged` 를 넘겼을 때 인디케이터가 `Clickable` 이 되어 `role="button"` + `tabindex="0"` 에 더해 `aria-label="Step N: 라벨"` 과, 현재 단계에는 `aria-current="step"` 이 붙습니다(`stepper.dart:295`). 내비게이션을 주지 않으면 인디케이터는 role 없는 평범한 `<div>` 로 남습니다(`stepper.dart:290`). 루트 `<div>` 에는 `list` / `group` 류 role 이 없습니다(`stepper.dart:181`).

가로 레이아웃의 폭 예약용 라벨 사본 두 개는 리더에서 제외됩니다 — Flutter 는 `ExcludeSemantics`(`stepper.dart:216`, `:226`), Web 은 `aria-hidden="true"`(`stepper.dart:221`, `:227`) 로 같은 처리를 합니다.

### 키보드

| 키 | Flutter | Web |
|---|---|---|
| `Tab` / `Shift+Tab` | `onStepChanged` 가 있을 때 단계마다 개별 tab stop | `onStepChanged` 가 있을 때 단계마다 개별 tab stop |
| `Enter` / `Space` | 포커스된 단계로 이동 (`onStepChanged(index)`) | 포커스된 단계로 이동 (`onStepChanged(index)`) |
| `ArrowLeft` / `ArrowRight` 로 단계 간 이동 | **없음** | **없음** |
| `Home` / `End` 로 첫/마지막 단계 | **없음** | **없음** |

컴포넌트가 바인딩하는 키는 `Enter` / `Space` 뿐입니다(`clickable.dart:14`). `onStepChanged` 를 넘기지 않으면 키보드로 도달할 수 있는 요소가 하나도 없습니다.

### 스크린 리더

- **Web** — 인디케이터 버튼의 이름은 `CouiLocalizations.stepperStepLabel` 에서 옵니다(`stepper.dart:298` → "Step 1: 계정" / "1단계: 계정"). 같은 라벨 텍스트가 바로 옆 노드에도 그대로 남아 있어, 브라우즈 모드에서는 버튼 이름과 라벨을 연달아 두 번 듣게 됩니다(가로 `stepper.dart:229`, 세로 `stepper.dart:152`).
- **Flutter** — 같은 문자열이 `CoUILocalizations.stepperStepLabel` 로 이미 존재하지만 위젯이 호출하지 않습니다(`coui_localizations.dart:433`). 그래서 대기·현재 단계 버튼은 숫자만 읽히고, **완료 단계 버튼은 내용이 체크 아이콘뿐이라 이름이 아예 없습니다**(`stepper.dart:289`). `aria-current` 에 해당하는 표시도 없습니다.

`onStepChanged` 가 없는 읽기 전용 스테퍼는 양 플랫폼 모두 번호와 라벨·설명이 평범한 텍스트로만 읽히고, 어느 단계가 현재인지는 굵기와 색으로만 표현됩니다.

진행이 바뀐 사실을 알리는 live region 은 양쪽 다 없습니다.

### 포커스 관리

- **진입 / 이탈 / 트랩** — 모두 없음. 오버레이가 아니라 인라인 진행 표시라 마운트·갱신 때 포커스를 옮기지 않고, `Tab` 은 스테퍼 밖으로 그대로 빠져나갑니다.
- 내비게이션이 켜지면 **단계 수만큼 tab stop 이 생깁니다** — roving tabindex 를 쓰지 않아 8 단계 스테퍼를 지나가려면 `Tab` 을 8 번 눌러야 합니다.
- `currentStep` 이 바뀌어도 포커스를 옮기지 않습니다. 눌린 인디케이터에 포커스가 그대로 남습니다.

### 알려진 제약

- **Flutter 인디케이터에는 이름도 현재 단계 표시도 없습니다** — Web 이 `aria-label` 과 `aria-current="step"` 을 붙이는 자리에 대응하는 `Semantics` 가 없어, 같은 스테퍼가 플랫폼에 따라 다르게 안내됩니다. 대안은 없습니다: 인디케이터는 위젯 내부에서 생성되고, `CoreStepItem` 은 `label` / `description` 만 받으며(`stepper_contract.dart:14`), Flutter `Stepper` 에는 attributes / Semantics 슬롯이 없습니다(`stepper.dart:39`).
- **완료 구간과 남은 구간의 커넥터가 색으로만 구분됩니다** — 두께는 같은 값을 쓰고 색 토큰만 `primary` ↔ `outlineVariant` 로 갈립니다(Flutter `stepper_style.dart:245`, Web `stepper_style.dart:679`). OS 의 색 강제 모드에서는 두 색이 같은 시스템 색으로 접히므로 **진행 구간이 통째로 사라집니다.** 현재 단계와 대기 단계의 원도 테두리 색(`primary` ↔ `outlineVariant`)으로만 갈려 같은 이유로 접힙니다. 라벨 굵기와 완료 단계의 체크 아이콘은 남으니, 진행률을 커넥터 색에만 의존해 읽히게 두지 마세요.
