# 비-유리 프리셋 렌더 스냅샷 — 도달 범위와 그 밖

> **적용 범위**: `defaultStyle` · `neoBrutalism` · `claymorphism` · `neumorphism` 네 프리셋이 표면 71 개를 어떻게 렌더하는지 고정한 기준선. 무엇을 잡고 무엇을 잡지 못하는지, 기준선을 언제 다시 찍는지.

## 왜 있나

이 Epic 은 반복해서 같은 문장을 쓴다 — **다른 프리셋은 한 픽셀도 안 바뀐다.** 근거는 그 네 프리셋이 재질을 진술하지 않으므로 역할 축이 해석할 것이 없다는 것이고, 설계상 참이다.

**설계상 참인 것과 렌더가 같은 것은 다른 진술이다.** 컴포넌트가 자기 역할을 나르도록 구조가 바뀌면, 재질을 진술하지 않는 프리셋 아래에서도 그리는 것이 달라질 수 있고 그때도 설계 논증은 그대로 건전하게 읽힌다. 이 기준선은 두 번째 진술만 본다.

**기준선은 구조가 바뀌기 전에 찍혀 있어야 한다.** 51 개 컴포넌트가 들어온 뒤에 찍으면 그 산출물이 기준선이 되고, 그것들이 무엇을 움직였는지는 영원히 물을 수 없다.

## 무엇을 읽나

렌더 트리에서 **chrome 을 칠하는 노드**를 페인트 순서대로 훑어 값으로 적는다:

| 노드 | 적는 것 |
|---|---|
| `RenderDecoratedBox` | 채움(알파 포함) · 네 변 보더 · 네 모서리 반경 · 캐스트 전 레이어 · 그라디언트 · shape |
| `RenderPhysicalModel` | elevation · 색 · 그림자 색 |
| `RenderOpacity` | 서브트리 알파 |
| `RenderBackdropFilter` | 필터 — 진술되지 않은 재질이 도착했다는 가장 뚜렷한 신호 |
| `RenderCustomPaint` | 페인터 **타입** (knock-out 캐스트 · 하이라이트 림) |

**위젯이 아니라 렌더 오브젝트를 읽는 이유**: 위젯 트리는 *무엇을 요청했는지*를 보여주고 렌더 트리는 프레임워크가 *무엇으로 해석했는지*를 보여준다. 컴포넌트가 어떤 위젯으로 박스를 그리는지 바꾸는 리팩터는 위젯 이름에 건 감시를 통과한다.

**픽셀이 아닌 이유**: 골든 이미지는 "바뀌었나" 에만 답하고 "무엇이" 에는 답하지 않는데, 프리셋 회귀가 실제로 묻는 것은 후자다. JSON 은 `"a": 1.0 → 0.502` 로 diff 된다.

여기에 더해, 각 프리셋의 **테마 재질 필드**(`surfaceOpacity`/`surfaceBlur`/`surfaceSheen`/…)를 한 줄로 함께 적는다. 렌더는 오늘 소비되는 값만 보여주므로, 아직 아무 컴포넌트도 읽지 않는 재질이 레시피에 들어오면 렌더에는 안 나타난다 — 이미 머지된 회귀가 나중에 누가 그 필드를 읽기 시작할 때를 기다리는 상태다.

## 도달하지 못하는 곳

부분 지원은 완전 지원처럼 보인다. 아래는 이 기준선이 **보지 않는** 축이고, 여기서 깨진 회귀는 이 그물을 그냥 통과한다.

- **밝기** — light 만 찍는다. dark 는 없다. 구조 회귀는 밝기와 무관하게 나타나므로 두 배의 기준선이 사는 만큼을 더 사지 못한다고 판단했고, 팔레트 축은 대비 가드가 따로 본다.
- **변형(variant)** — 각 표면의 기본 변형 하나만. 프리뷰 레지스트리가 받는 다른 변형은 렌더되지 않는다.
- **플랫폼** — Flutter 만. Web 은 이 그물의 대상이 아니다(파리티 게이트가 다른 축을 본다).
- **상태** — 쉬는 상태만. hover · focus · pressed · disabled 는 찍히지 않는다.
- **기하와 텍스트** — 크기 · 위치 · 클립 모양 · 타이포그래피는 적지 않는다. chrome 을 하나도 건드리지 않고 레이아웃만 바꾸는 변경은 통과한다.

## 기준선을 다시 찍을 때

```bash
cd packages/coui_flutter
UPDATE_PRESET_SNAPSHOTS=1 flutter test \
  test/theme/preset_snapshot/preset_render_snapshot_test.dart
```

다시 찍는 것은 고치는 것이 아니라 **결정**이다. diff 는 "안 바뀌었어야 할 네 프리셋에서 무엇이 바뀌었는가" 의 서술이고, 그것을 만든 PR 안에 그 설명이 같이 있어야 한다.

그 결정에는 리뷰어가 붙는다 — 이 기준선 디렉터리는 `.github/CODEOWNERS` 에 등록돼 있고, `main` 은 `require_code_owner_reviews` 를 요구한다. 다시 찍은 결과를 `main` 으로 가져가려면 code-owner 승인을 거친다(`enforce_admins` 가 켜져 있어 `--admin` 우회도 없다). 다만 **`main` 이 base 인 PR 에서만 그렇다** — CODEOWNERS 는 PR 의 base 브랜치에서 읽히므로, 중간 계층 브랜치를 base 로 하는 PR 은 그 브랜치에 보호가 걸려 있지 않는 한 이 승인을 거치지 않는다.

## 강제

- **테스트** — `packages/coui_flutter/test/theme/preset_snapshot/preset_render_snapshot_test.dart` (295 항목, ~10s). 태그가 없어 패키지 스위트(`melos run test:flutter`)에 항상 포함된다.
- **CI** — 같은 파일을 `.github/workflows/ci.yaml` 의 `Preset Render Snapshot` 스텝이 한 번 더, 이름을 붙여 먼저 돌린다. 두 경로인 이유는 한쪽 편집만으로는 게이트가 사라지지 않게 하기 위해서다 — 워크플로 스텝만 있으면 워크플로 편집이 지우고, 패키지 스위트만 있으면 3,000 줄 안의 한 줄로 실패한다.
- **표면 목록** — `docs/_glass-survey-full.json` 에서 `role ∈ {content, functional}` 로 유도한다. 손으로 세지 않으므로 이 Epic 의 다른 산출물과 갈릴 수 없고, 서베이가 바뀌면 기준선 집합 검사가 먼저 실패한다.
- **재촬영 승인** — `/packages/coui_flutter/test/theme/preset_snapshot/baselines/` 가 `.github/CODEOWNERS` 에 등록돼 있다. 등록 자체가 빠지는 것은 `scripts/guards/structure/check_codeowners_ratchet_coverage.sh` 가 CI 에서 센다 — ratchet 은 "새 위반 net-new 0" 만 강제하고 기준선을 늘리는 완화는 그 완화를 담은 PR 이 스스로 통과시키기 때문이다.
- **프리셋 목록** — 네 이름을 적어 둔다(재질 유무에서 유도하지 않는다). 유도하면 `neoBrutalism` 에 재질이 새는 순간 그 프리셋이 감시 집합에서 **빠져** 세 개만 검사하고 green 을 보고한다. 대신 "덮지 않는 프리셋은 유리 하나뿐" 을 따로 검사해, 프리셋이 늘면 판단을 적도록 강제한다.

### 실패시켜 봤는가

세 갈래 전부. 실패시켜 보지 않은 그물은 그물이 아니고, 이 레포는 그것을 반복해서 겪었다.

| 주입 | 결과 |
|---|---|
| `neoBrutalism` 레시피에 재질 한 벌(`opacity 0.5` · `blur 12`) | **18 항목 빨강** — 렌더 16 개(`neoBrutalism/card` 의 노드 1 이 `backdrop` 으로 바뀌고 채움 알파가 `1.0 → 0.502`), 테마 재질 1 개, "이 프리셋들은 재질을 진술하지 않는다" 전제 1 개 |
| 기준선 파일 하나 삭제 | **그 프리셋 1 항목 빨강** — 나머지 70 개가 조용히 통과하는 대신 "기준선 없음" 으로 멈춘다 |
| 기준선에서 표면 하나 제거(서베이와 어긋남) | **집합 검사 빨강** — 덮는 표면이 줄어든 것을 통과로 읽지 않는다 |

세 경우 모두 되돌리면 295 개 전부 통과한다.
