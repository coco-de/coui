# MockupFoldable

가운데가 접히는 기기를 그린 프레임 목업입니다. 접힘 각도 `foldAngle` 하나로 닫힘 · 반접힘 · 펼침과 그 사이의 모든 각도를 그리고, 각도가 바뀌면 기기가 3D 로 접히고 펴집니다. 펼치면 가로로 놓인 태블릿이고, 닫으면 접힌 반쪽의 뒷면에 폰 화면(커버 화면)이 나옵니다.

화면 위쪽을 가로지르는 상태 표시줄은 없습니다. 운영체제의 표시는 화면 오른쪽 끝의 세로 열 — 상태 아일랜드 — 에 놓입니다. 커버 화면에서는 맨 위가 카메라이고 그 아래에 시각과 상태 표시가 오며, 안쪽 화면에는 카메라 없이 시각과 상태 표시만 있습니다.

## 사용 시기 (When to Use)

**이 컴포넌트를 사용하세요:**

- 랜딩이나 문서에서 앱 화면을 폴더블 기기 안에 보여줄 때
- 앱이 접힘에 어떻게 반응하는지(커버 화면 · 반접힘 · 펼침)를 한 화면에서 시연할 때

**대신 다른 컴포넌트를 사용하세요:**

- 접히지 않는 폰 · 태블릿 프레임은 [`MockupDevice`](/components/mockup-device)
- 브라우저 · 앱 창 프레임은 [`MockupBrowser`](/components/mockup-browser)

## 기본 사용법 (Basic Usage)

```dart
// 펼친 기기 — foldAngle 을 적지 않으면 180(펼침)이다
MockupFoldable(
  child: Text('앱 화면').bodyMedium.onSurface,
)

// 책처럼 반쯤 연 기기
MockupFoldable(
  foldAngle: CoreMockupFold.halfOpen,
  child: Text('앱 화면').bodyMedium.onSurface,
)

// 닫힌 기기 — child 는 커버 화면에 놓인다
MockupFoldable(
  foldAngle: CoreMockupFold.closed,
  child: Text('앱 화면').bodyMedium.onSurface,
)

// 각도를 바꾸면 기기가 그 각도로 접히고 펴진다
MockupFoldable(
  foldAngle: _angle,
  child: Text('앱 화면').bodyMedium.onSurface,
)

// 슬라이더로 각도를 직접 끌 때는 기다리지 않고 따라가게 한다
MockupFoldable(
  foldAngle: _angle,
  mockupFoldableStyle: const CoreMockupFoldableStyle(
    duration: Duration.zero,
  ),
  child: Text('앱 화면').bodyMedium.onSurface,
)
```

화면에 놓인 `child` 는 실제 폴더블 기기에서와 같은 호출로 접힘을 읽습니다.

```dart
final fold = FoldScope.of(context);
// 반접힘: fold.posture == CoreFoldPosture.book, fold.segments 가 좌우 두 칸
// 펼침: fold.posture == CoreFoldPosture.flat, 한 칸
// 커버 화면: fold.posture == null, 접힘 없음
```

## 스타일 시스템 (Style System)

### `mockupFoldableStyle`

기기의 겉모습은 두 `MockupDevice` 의 것입니다. 펼친 본체는 `innerDeviceStyle`, 커버는 `coverDeviceStyle` 로 바꾸고, 두 값 모두 [`CoreMockupDeviceStyle`](/components/mockup#coremockupdevicestyle) 입니다. 커버의 크기는 고를 수 없습니다 — 언제나 펼친 본체의 절반 너비에 같은 높이입니다.

```dart
MockupFoldable(
  mockupFoldableStyle: const CoreMockupFoldableStyle(
    // 반쪽을 더 두껍게, 더 가까이서 본 것처럼
    thickness: CoreSize.size16,
    perspective: 2,
    // 커버의 베젤만 더 두껍게
    coverDeviceStyle: CoreMockupDeviceStyle(bezelWidth: CoreSpace.space8),
  ),
  child: Text('앱 화면').bodyMedium.onSurface,
)
```

값이 정해지는 순서는 디자인 시스템 기본값 → `CoreMockupFoldableTheme.style`(프로젝트 공통) → `mockupFoldableStyle`(이 기기 하나)입니다.

### 상태 아일랜드

화면 오른쪽 끝의 열과 그 안에 놓이는 것 — 커버의 카메라, 시각, 상태 표시(와이파이를 감싼 고리와 그 아래 점 넷) — 은 `island*` 필드로 바꿉니다.

- 길이(`islandWidth` · `islandOffset` · `islandCameraSize`)는 iOS 포인트로 적습니다. 그 화면을 그리는 `MockupDevice` 가 운영체제의 길이를 그리는 배율로 그려지고, 기본 배율은 0.478 입니다 — 기본 너비의 안쪽 화면(458px)이 958 포인트짜리 화면을 나타내는 배율입니다. 본체의 너비를 바꿔도 아일랜드의 크기는 그대로입니다.
- 색과 글자는 `islandCameraColor` · `islandTextStyle` · `islandIconColor` · `islandDotColor` 입니다. 시각과 상태 표시는 화면의 밝기를 따르고, 카메라는 어느 밝기에서나 같은 색입니다.
- 시각의 문구(`9:41`), 상태 표시의 그림, 카메라 · 시각 · 상태 표시 사이의 간격은 견본이라 바꿀 수 없습니다. `MockupDevice` 의 상태 표시줄과 같습니다.
- 열의 바탕은 화면의 바탕색입니다. `child` 가 자기 바탕색을 칠하면 열만 다른 색으로 남으므로, 그때는 두 얼굴의 `backgroundColor` 를 같은 색으로 적습니다.

```dart
MockupFoldable(
  mockupFoldableStyle: const CoreMockupFoldableStyle(
    // 열을 넓히고 상태 표시의 색을 바꾼다
    islandWidth: CoreSize.size112,
    islandIconColor: CoreColor.token(CoreColors.primary),
  ),
  child: Text('앱 화면').bodyMedium.onSurface,
)

// 화면을 실제 크기(1 포인트 = 1px)로 보여줄 때는 두 얼굴의 배율을 1 로 적는다
MockupFoldable(
  width: 980,
  mockupFoldableStyle: const CoreMockupFoldableStyle(
    innerDeviceStyle: CoreMockupDeviceStyle(
      landscapeSystemBarReferenceScale: 1,
    ),
    coverDeviceStyle: CoreMockupDeviceStyle(systemBarReferenceScale: 1),
  ),
  child: Text('앱 화면').bodyMedium.onSurface,
)
```

## 동작 스펙 (Behavior)

### 인터랙션

- 프레임 자체는 입력을 받지 않습니다. 각도는 호출부가 `foldAngle` 로 정하고, 버튼이나 슬라이더 같은 컨트롤도 호출부가 둡니다.
- `child` 는 화면에서 상태 아일랜드의 열을 뺀 자리에 놓입니다. 홈 제스처 바를 켰으면 그 자리도 비웁니다.
- `child` 의 컨트롤은 화면이 한 장으로 놓인 동안 그대로 동작합니다 — 펼친 안쪽 화면(180°)과 커버 화면입니다.
- 상태 아일랜드는 입력을 받지 않습니다.
- 안쪽 화면이 접혀 있는 동안(180° 미만)에는 두 반쪽이 서로 다른 평면에 놓이므로 `child` 를 조작할 수 없는 사본으로 그립니다.

### 상태 전환

- 각도가 30° 이하이면 커버 화면이, 그보다 넓으면 안쪽 화면이 켜지고 `child` 가 그 화면 크기로 다시 놓입니다. 화면이 바뀌어도 `child` 의 상태는 유지됩니다.
- 켜진 화면이 바뀌는 30° 에서는 두 화면이 모두 꺼져 있습니다. 커버 화면은 10° 에서 30° 로 가며 어두워지고, 안쪽 화면은 30° 에서 60° 로 가며 밝아집니다.
- 안쪽 화면의 `child` 는 화면 가운데를 세로로 지나는 접힘 하나를 읽습니다. 150° 이상이면 펼쳐진 접힘(화면 한 칸), 그 미만이면 반쯤 접힌 접힘(좌우 두 칸)입니다. 커버 화면에서는 접힘이 없습니다.
- 컴포넌트가 차지하는 자리는 어느 각도에서나 펼친 본체의 크기입니다. 닫힌 기기는 그 가운데에 서고, 접는 동안 보는 쪽으로 다가온 반쪽은 그 자리 밖으로 조금 나가 그려집니다.

### 애니메이션

- `foldAngle` 이 바뀌면 지금 그려진 각도에서 새 각도까지 `CoreDuration.slow`(500ms) 동안 `CoreEasing.move` 곡선으로 움직입니다. 움직이는 도중에 값이 다시 바뀌면 그 자리에서 새 각도로 향합니다.
- 길이와 곡선은 `mockupFoldableStyle` 의 `duration` · `curve` 로 바꿉니다. `duration: Duration.zero` 이면 각도를 그 자리에서 따라갑니다.
- 운영체제의 동작 줄이기 설정이 켜져 있으면 움직이지 않고 새 각도로 바로 바뀝니다. 기본 길이를 포함해 500ms 이하의 움직임이 그렇고, 그보다 길게 적은 `duration` 은 그대로 움직입니다.

## 사용 가이드라인 (Usage Guidelines)

### Do

<Callout type="tip">

**슬라이더처럼 각도를 연속으로 바꾸는 컨트롤에는 `duration` 을 0 으로 둡니다**

```dart
MockupFoldable(
  foldAngle: _angle,
  mockupFoldableStyle: const CoreMockupFoldableStyle(
    duration: Duration.zero,
  ),
  child: screen,
)
```

이유: 기본 길이(500ms)로 두면 기기가 손가락을 뒤늦게 따라옵니다.

</Callout>

### Don't

<Callout type="warning">

**반접힘 상태에서 조작해야 하는 화면을 넣지 않습니다**

```dart
MockupFoldable(
  foldAngle: CoreMockupFold.halfOpen,
  child: CheckoutForm(), // 접힌 화면에서는 입력할 수 없다
)
```

이유: 접혀 있는 동안의 화면은 조작할 수 없는 사본입니다. 조작을 보여주려면 펼치거나 닫은 상태를 씁니다.

</Callout>

- 스크린샷처럼 가벼운 자식을 넣습니다. 실제 앱 UI 의 컨테이너가 아니라 문서 · 프레젠테이션 · 데모용입니다.
- 화면의 모서리는 둥글고 위쪽에 띠가 없습니다. 모서리에 바짝 붙인 내용은 잘리므로, `child` 에 안쪽 여백을 두거나 가운데에 놓습니다.

## 접근성 (Accessibility)

### 역할

정적 기기 프레임이며 운영체제 역할을 붙이지 않습니다. 안의 `child` 는 자기 시맨틱을 유지합니다.

### 키보드

프레임 자체의 키보드 조작은 없습니다. 각도를 바꾸는 컨트롤은 호출부의 것이고, 그 컨트롤이 자기 키보드 동작을 가집니다.

### 스크린 리더

화면이 한 장으로 놓인 동안(펼침 · 커버)에는 `child` 가 그대로 읽힙니다. 안쪽 화면이 접혀 있는 동안에는 보이는 것이 조작할 수 없는 사본이라 `child` 가 보조 기술에 드러나지 않습니다. 상태 아일랜드(카메라 · 시각 · 상태 표시)는 운영체제를 그린 그림이라 양 플랫폼 모두 보조 기술에서 숨깁니다. 접힌 각도를 말로 알려주지는 않으므로, 각도가 뜻을 가지면 호출부가 그 상태를 글로 함께 적습니다.

### 포커스 관리

프레임은 포커스를 옮기거나 가두지 않습니다. 안쪽 화면이 접혀 있는 동안에는 `child` 가 포커스를 받지 않습니다 — 보이는 것이 사본이라 포커스가 놓인 자리를 그릴 수 없기 때문입니다.

### 알려진 제약

접혀 있는 동안의 화면은 조작할 수 없고 보조 기술에도 드러나지 않습니다. 그 상태로 오래 보여주는 화면이면 무엇이 그려져 있는지를 호출부가 글로 함께 적습니다. 기기 그림만으로 화면의 대체 텍스트가 생기지 않으므로, 기기 모양이나 스크린샷 자체의 설명이 필요할 때도 호출부가 제공합니다.

## 크로스 플랫폼 차이점 (Platform Differences)

| 항목 | Flutter | Web |
|------|---------|-----|
| 두 얼굴 | `MockupDevice` 두 개 (가로 태블릿 · 폰) | 같다 |
| 반쪽의 자리 | Core 가 계산한 변환 행렬을 그대로 `Transform` 에 넘김 | 같은 단계를 `rem` 길이의 CSS transform 함수로 적음 — 루트 글자 크기를 따라간다 |
| 접힌 화면의 사본 | 화면을 이미지로 떠서 두 반쪽에 그림. `child` 가 다시 그려지면 이미지도 다시 뜬다 | 안쪽 기기를 반쪽마다 한 번 더 그림. `child` 가 안에 가진 상태는 처음 값으로 보인다 |
| 접힌 동안의 `child` | 입력 · 포커스 · 시맨틱을 막는다 | 보이지 않게 두고 `inert` 로 막는다 |
| 움직임 | `AnimationController` | 브라우저의 프레임마다 각도를 다시 계산. 수화되지 않은 페이지에서는 각도가 고정이다 |
| `child` 가 읽는 접힘 | 화면의 `MediaQuery` 에 접힘을 실어 `FoldScope.of` 가 읽음 | `FoldLayoutScope` 로 감싸 `FoldScope.of` 가 읽음 |
| `child` 가 비우는 열 | 화면의 `MediaQuery` 에 오른쪽 여백으로 싣고 `SafeArea` 로 비움 — `child` 안의 `SafeArea` 가 같은 여백을 한 번 더 비우지 않는다 | 콘텐츠 상자의 오른쪽 안쪽 여백으로 비움 |
| 상태 표시의 그림 | 벡터 경로를 직접 그림 | 같은 경로를 인라인 SVG 로 그림 |
| 호스트 속성 | key | id · classes · css · attributes · 이벤트 전달 |

- Flutter 의 사본은 `child` 가 스크롤 뷰 안에서처럼 자기 안쪽에서만 다시 그려질 때는 그 변화를 바로 알지 못합니다. 그런 변화는 접는 움직임이 끝날 때와 이 컴포넌트가 다시 빌드될 때 반영됩니다. 웹뷰 · 지도 같은 플랫폼 뷰는 사본에 찍히지 않습니다.
- Web 은 접힌 동안 `child` 를 세 번 짓습니다(보이지 않는 원본 하나와 반쪽마다 사본 하나). 문서에서 하나뿐이어야 하는 것 — `GlobalKey`, 요소 `id`, 같은 이름의 라디오 묶음 — 을 가진 `child` 는 접힌 상태로 쓰지 않습니다.
- Chrome 은 3D 로 돌린 큰 레이어를 낮은 해상도로 그립니다. Web 에서 본체 너비가 약 800px 를 넘으면 접힌 동안의 화면이 고해상도 디스플레이에서 조금 흐리게 보입니다.
- Web 에서 `child` 의 레이아웃이 뷰포트 폭을 읽는 CSS 미디어 쿼리에 기대면, 화면이 커버로 바뀌어도 그 레이아웃은 바뀌지 않습니다. 화면 크기에 따라 달라져야 하는 레이아웃은 자기 상자의 폭을 읽게 합니다.
- Figma 라이브러리에는 이 컴포넌트가 없습니다. 캔버스는 접힘 각도와 움직임을 싣지 못합니다.
