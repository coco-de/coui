# 리디자인 문서

디자이너가 쓴 리디자인 문서를 모아 두는 곳이다 — 전수조사 · 제안 · 결정 · 코드 인계. 리디자인 작업을 시작하는 세션(사람이든 에이전트든)은 여기서 그 계열에 해당하는 문서를 먼저 읽는다.

## 이 폴더가 답하는 것과 답하지 않는 것

| 질문 | 어디서 |
|---|---|
| 무엇을 왜 바꾸기로 했나 · 어떤 선택지를 버렸나 | **여기** |
| 지금 누가 무엇을 하고 있나 · 어디까지 반영됐나 | ZenHub 워크스페이스 `CoUI`(저장한 보기 "리디자인")와 `redesign` 라벨 이슈 |
| 컴포넌트의 실제 값(색 · 크기 · 간격) | 코드 계약(`CoreXxxStyle` default · 토큰) |
| 협업 절차(역할 · 단계 · 이슈 쓰는 법) | [`../contributing/design-collaboration.md`](../contributing/design-collaboration.md) |

**왜 값을 여기서 읽지 않는가**: 문서에 적힌 값은 그 문서를 쓴 날의 값이다. 코드가 다시 바뀌어도 문서는 따라오지 않는다 — 값의 정본은 코드 하나다(`.claude/rules/process/design-code-handoff.md` "문서 경계").

## 문서마다 머리말에 상태를 적는다

| 상태 | 뜻 |
|---|---|
| **제안** | 아직 결정되지 않았다. 여기 적힌 규칙을 근거로 코드를 바꾸지 않는다 |
| **확정** | 디자이너가 결정했다. 반영은 리디자인 이슈로 받는다 |
| **기록** | 한 시점의 실측 · 인계다. 그 뒤 코드가 바뀌었을 수 있다 |

제안이 확정되면 새 파일을 만들지 않고 그 문서의 머리말 상태와 결정 내용을 고친다. 문서끼리는 파일 이름으로 서로 가리키므로 **파일 이름을 바꾸지 않는다.**

## 문서를 넣는 방법

디자이너가 세션에 파일을 건네면, 그 세션이 워크트리에서 이 폴더에 넣고 PR 로 머지한다(문서만 바꾸는 PR). 이미 있는 문서의 새 판이면 같은 파일을 덮어쓴다 — 이전 판은 git 이력에 남는다.
